# 0005 发布分发与现场排障

- 状态：已实现（v1 交付部分；正式签名与上架待 Phase 4）
- 对应阶段：Phase 4（v1 交付部分随 Phase 1 生效）
- 关联：`docs/PLAN.md` 第 6 节、`docs/design/0003-平板运行形态与门禁.md`

## 1. 背景与目标

明确 v1 成品的构建产物、签名、分发与升级方式，以及摊位现场的排障手段。

## 2. 构建与签名

- v1 使用 debug 签名产物 `app/build/outputs/apk/debug/app-debug.apk` 分发（由 `scripts\build-and-install.bat` 生成）。
- 正式 release keystore、渠道与上架方式留待 Phase 4，届时另立设计文档。
- ABI：仅出 arm64-v8a 单 ABI。
- 混淆：v1 关闭 minify，避免 NanoHTTPD 反射相关问题。

## 3. 安装与升级

- 安装：`adb install -r app-debug.apk`；或 U 盘拷贝后在平板上允许「未知来源」手动安装。
- 升级：覆盖安装保留数据；Room schema 变更需配套迁移（`exportSchema = true`，schema JSON 入库 `app/schemas/`）。
- 卸载会清除数据：卸载前先导出备份（见 `docs/design/0004`）。

## 4. 现场排障

- 应用日志：`TpLog` 写 `filesDir/logs/app-<date>.log`，保留最近 7 天。
- 一键收集：`scripts\collect-logs.*`（Phase 1 交付）导出 logcat 与应用日志，便于离线分析。
- 常见问题：
  - 手机连不上：确认同一网段；平板 IP 变化后重新扫码；确认 token 是否已更换。
  - 展示页掉帧：按 `docs/PLAN.md` 第 8 节门禁逐级降级。
  - 忘记 PIN：清除数据或重装（先导出备份）。

## 5. 测试与验收

- 覆盖安装后数据不丢、展示页正常。
- 日志按天切分且不超过 7 天。
- 排障清单逐条可执行。

## 6. 未决事项

- 正式签名密钥的生成与保管方式（Phase 4）。
- 是否提供应用内「导出诊断包」入口。

## 7. 实现位置与验证结果（Phase 1）

- 日志：`app/src/main/java/com/tanpai/menu/logging/TpLog.kt`，写 `filesDir/logs/app-<date>.log`，保留 7 天，默认异常处理器记录崩溃。
- 一键收集：`scripts/collect-logs.ps1` + `scripts/collect-logs.bat`，产出 `<输出目录>/device.txt`、`logcat.txt`、`app-logs/`；输出默认落在 `dist/logs/<时间戳>/`（已加入 `.gitignore`）。
- 构建分发：`scripts/build-and-install.*` 产出并安装 `app/build/outputs/apk/debug/app-debug.apk`（debug 签名、单 ABI、关闭 minify）。
- 真机验证：脚本实跑成功，产出目录含设备信息、logcat 与应用日志，中文无乱码；覆盖安装后数据保留。
