# 0011 展示页默认外观与整数价格

- 状态：已实现（2026-10-06）
- 对应阶段：Phase 1 修订（展示页外观）
- 关联：`docs/design/0006-展示页紧凑布局与默认菜单.md`、`docs/design/0007-展示页背景图片.md`、`docs/design/0009-展示页内置背景样式.md`、`docs/design/0010-展示页微信二维码.md`、`docs/architecture.md`

## 1. 背景与目标

0010 落地后店主在真机上提出四条修订：默认背景偏素（纯色底）、整数价格多出 `.00` 噪声、微信二维码需要一张开箱即用的默认图、设置弹窗里「背景蒙版不透明度」滑条被二维码区挤到了后面。四条互相独立但同属「展示页默认外观」这一轮，合并在本文档。

目标：

- 默认背景为内置样式「喜庆红」（`warm_red`），背景蒙版不透明度默认由 30% 降为 25%。
- 整数价格不显示小数位（`¥10`），有角分时仍保留两位（`¥10.50`）。
- 内置一张默认微信二维码；店主未上传时展示它，上传后以自己的为准，「恢复默认」回到内置图。
- 修正设置弹窗顺序：蒙版滑条紧跟其标题行，二维码区排在其后。
- 不改数据模型与备份格式，不引入第三方依赖。

## 2. 方案设计（含取舍）

### 2.1 默认背景：喜庆红

样式清单仍是唯一真源：`ui/theme/BackgroundStyles` 新增 `DEFAULT_ID = "warm_red"`（喜庆红）与 `byIdOrDefault(id)`；展示页由 `byIdOrDefault(backgroundStyleId)` 取样式，未设置过背景的设备开箱即得红底。默认只作用于「读不到样式」的场景，`SettingsStore` 保持存储原值（null = 未设置），数据层不反向依赖 UI 层。

- `AdminViewModel.clearBackground()`（按钮文案「恢复默认」）由写 `null` 改为写默认样式 id：语义是回到喜庆红，而不是回到纯色底。
- 管理页样式选中态：`AdminScreen` 传入选中的样式 id 时，若有自定义背景图则传 `null`——否则用户换了自定义图后，样式区仍会高亮喜庆红，看起来像两种背景同时生效。
- 取舍：不新增「无背景」选项（店主明确不需要），因此不再存在「纯色底」这一态，背景恒为「自定义图或某款样式」。

### 2.2 蒙版默认 25%

`DEFAULT_BACKGROUND_SCRIM_PERCENT` 由 30 改为 25。只影响未手动拖过滑条的设备；已存值不变（`getInt` 读到的仍是用户值）。

### 2.3 整数价格去掉小数

`domain/PriceFormatter.formatYuan` 改为：分位为 0 时只输出整数部分，否则保留两位。展示页（`¥10 / 份`）与管理页列表共用该函数，一处改动两端生效；分单位存储的网络/数据库契约不变。

### 2.4 内置默认微信二维码

- 新增资源 `app/src/main/res/drawable-nodpi/wechat_qr_default.png`（店主提供的二维码，585×570）。`-nodpi` 保证不被系统按密度缩放，避免二维码模块被插值糊掉。
- 图片模型由 `File` 放宽为 `Any`（Coil 模型）：`DisplayScreen` 计算 `wechatQrModel = 已上传文件（存在时）?: R.drawable.wechat_qr_default`，`DisplayTopBar` 与 `WechatQrOverlay` 直接消费该模型，入口与放大浮层共用同一张图。
- 未上传、上传后文件被外部删除，都回退到内置图；因此顶栏入口恒常驻，不再有「未设置则不显示」的分支。
- 管理页「微信二维码」区状态文本改为三态：已上传显示「已设置」，未上传显示「使用内置默认」；清除按钮文案由「清除」改为「恢复默认」，未上传时禁用。
- 取舍：不把内置图拷进 `filesDir`——它是 APK 资源，天然不参与启动孤儿图清理、不参与备份、不需要数据迁移，也不会因为「清除」而丢失。

### 2.5 设置弹窗顺序修复

原顺序把蒙版标题行与滑条拆开了（新增二维码区时插在中间）。修正为：

`菜品卡片不透明度（标题 + 滑条）→ 内置样式色卡 → 背景图（状态 + 按钮 + 错误提示）→ 背景蒙版不透明度（标题 + 滑条）→ 微信二维码（状态 + 按钮 + 错误提示）`。
## 3. 接口与数据模型变化

| 位置 | 变化 |
| --- | --- |
| `domain/PriceFormatter.kt` | `formatYuan` 输出契约变化：整数金额无小数位，有角分保留两位 |
| `data/SettingsStore.kt` | `DEFAULT_BACKGROUND_SCRIM_PERCENT` 30 → 25 |
| `ui/theme/BackgroundStyles.kt` | 新增 `DEFAULT_ID = "warm_red"` 与 `byIdOrDefault(id)`（查不到时回退默认样式） |
| `ui/admin/AdminViewModel.kt` | 无自定义背景图时选中态回退默认样式；`clearBackground()` 重置为默认样式 id |
| `ui/admin/AdminScreen.kt` | 蒙版滑条移到标题行之后；二维码区状态改为「已设置 / 使用内置默认」与「恢复默认」按钮 |
| `ui/display/DisplayScreen.kt` | 背景取 `byIdOrDefault`，不再有「无背景」分支；二维码模型由 `File` 改为 `Any`（上传文件 ?: 内置资源 id），入口恒常驻 |
| `ui/display/WechatQrOverlay.kt` | `qrFile: File` → `qrModel: Any` |
| `res/drawable-nodpi/wechat_qr_default.png` | 新增：内置默认微信二维码 |
| `res/values/strings.xml` | 新增 `settings_wechat_qr_default`（使用内置默认）；`settings_wechat_qr_clear` 改为「恢复默认」 |

无 Room 表结构、数据模型、备份格式（仍 `format 1`）与网络协议变化。

## 4. 边界与失败场景

| 场景 | 处理 |
| --- | --- |
| 未设置过背景 | 展示喜庆红 + 25% 蒙版 |
| 已设置过其他样式 / 自定义图 | 保持用户值，不受默认变化影响 |
| 换自定义背景图 | 样式区不再高亮任何卡片，避免「两种背景同时生效」的错觉 |
| 未上传二维码 | 展示内置二维码，入口正常显示 |
| 上传后文件被外部删除 | 回退内置二维码，不崩溃、不空窗 |
| 「恢复默认」二维码 | 回到内置二维码，入口仍在 |
| 价格为整数 / 含角分 / 为 0 / 为负 | `¥10` / `¥10.50` / `¥0` / `-¥1` |

## 5. 测试与验收

- JVM 单测：`PriceFormatterTest` 五例（`¥0`、`¥12`、`¥3.05`、`¥9999.99`、`-¥1`）；`BackgroundStylesTest` 增三例断言 `DEFAULT_ID` 指向内置样式、`byIdOrDefault` 在 null / 未知 id 时回退默认样式、已知 id 原样返回。
- 仪表测试：`WechatQrOverlayTest` 现有 3 项（可见 / 自动复原 / 点击复原）继续通过，并补一项「以资源 id 作模型渲染可见」。
- 真机验收（Teclast T10）：默认即喜庆红 + 25% 蒙版；价格显示 `¥10 / 份`；未上传二维码时顶栏小码为内置图，点击放大可扫、5 秒自动复原；设置弹窗中蒙版滑条紧跟标题行。
- 门禁：`assembleDebug` + `testDebugUnitTest` + `connectedDebugAndroidTest` 通过。

## 6. 验证记录

- 构建与单测：2026-10-06，JDK 17 + Gradle 8.9，`assembleDebug`、`testDebugUnitTest` 通过（单测 `PriceFormatterTest` 5 项、`BackgroundStylesTest` 9 项）。
