# 0020 手机客户端编辑

- 状态：已实现（M11，2026-10-07）
- 对应阶段：Phase 3（M11）
- 关联：`docs/design/0019-手机客户端配对与只读浏览.md`、`docs/design/0002-局域网配对与同步.md`（第 4 节）、`docs/design/0001-菜单数据模型与接口契约.md`、`docs/design/0015-主机服务接口实现.md`、`docs/architecture.md`

## 1. 背景与目标

M10 交付了「配对 → 全量快照 → 增量事件 → 断线只读」的只读客户端，手机只能看不能改。M11 在同一个客户端形态上补齐编辑能力，让老板用手机也能完成日常经营动作，不必每次回到平板。

目标：

1. 手机端在只读浏览之上增加「管理模式」，能力对齐平板管理页：分类增删改、菜品增删改、传图（相册 / 拍照）、卖出 / 撤销 / 沽清 / 恢复、恢复默认菜单。
2. 写命令统一走「提交即禁用、等广播对齐」：提交期间禁用该行操作，收到主机广播（版本前进）后解除；不做真乐观更新与回滚。
3. 平板侧可一键关闭手机编辑（默认开启）：关闭后手机端的写请求被主机拒绝并给出中文提示。
4. 撤销语义由「仅限本机最后一条」改为「全局最后一条卖出记录」，使手机与平板可以互相撤销对方的卖出。

## 2. 方案设计（含取舍）

### 2.1 编辑入口与交互（取舍：管理模式开关）

- 默认仍是只读浏览页；顶栏在 `在线 && 允许编辑` 时显示「管理 / 完成」按钮，进入管理模式后同一页内换一套操作入口。
- 管理模式：
  - 分类行末尾追加「＋ 分类」chip 新增分类；长按某个分类 chip 弹出「重命名 / 改排序」「删除分类」。
  - 菜品行右侧直显「卖出」「撤销」（仅启用库存的菜品）与「沽清 / 恢复」；点整行打开菜品编辑弹窗，弹窗内含「删除菜品」。
  - 底部悬浮按钮「＋ 新增菜品」（新增到当前选中分类）；顶栏「⋯」菜单内含「恢复默认菜单」（二次确认）。
- 取舍：不采用「长按菜品弹操作菜单」（操作层次多一层），也不直接复用平板管理列表（手机上浏览体验变差）。手机屏窄，五个按钮平铺会挤压菜名，因此主操作直显、编辑与删除收进弹窗。
- 失败提示用底部 `Snackbar` 展示主机返回的中文 `message`；网络类失败自动重试一次，仍失败提示「重试」。

### 2.2 同步语义（与 `docs/design/0002` 第 4 节的差异与修订）

- `0002` 第 4 节原表述为「客户端先乐观更新本地镜像，再提交；失败回滚」。M11 修订为：
  - 客户端**不**修改本地镜像，提交期间仅把该行置为「提交中」并禁用；
  - 请求成功后等待镜像版本前进（即等到主机广播的增量事件或快照），最长 5 秒；超时则主动拉一次 `/state` 对齐后解除；
  - 请求失败（校验 / 冲突 / 断线 / 权限）直接解除并提示主机中文错误，不需要回滚。
- 取舍：落库真值只有主机一份，客户端镜像始终由主机事件驱动，避免「本地改动未落库却被当作真值」的中间态；代价是点头后约 0.1–0.5 秒的等待。
- 版本规则不变：`ClientMirror` 仍只接受 `version` 严格大于本地的事件，`snapshot` 无条件全量替换。

### 2.3 「允许手机编辑」开关与角色识别（取舍：软约束）

- 平板设置弹窗「手机控制端」区块新增「允许手机编辑」开关，默认开启，落盘 `SettingsStore.clientEditsEnabled`。
- 手机端对**所有** REST 请求附带 `X-Device-Id: <本机 deviceId>` 与 `X-Device-Role: client`；主机在处理写方法（POST / PATCH / DELETE）时，若角色为 `client` 且开关关闭，直接返回 `403 forbidden`（`/pair` 与全部 GET 不受限）。
- 手机端感知方式：`GET /state` 增加 `clientEditsEnabled`；开关切换时主机向所有连接广播一次 `snapshot`，在线手机立刻隐藏「管理」入口。
- 取舍：主机当前只有一条共享 token（HTTP 侧无法区分调用方），要做到「按身份强制」需要引入独立客户端 token 与两套鉴权。M11 选择请求头软约束：它拦得住「手机 App 的正常写请求」，拦不住刻意伪造请求头的攻击者。本工程的前提是摊位专用网络 + 明文 HTTP，token 本身也以明文传输，因此该局限可接受，并在此显式记录。

### 2.4 图片上传

- 手机端从相册或拍照取图 → 本机压缩成 JPEG 字节（长边 1280、质量 80，与主机 `ImageStore` 默认一致）→ `POST /api/v1/images`（multipart 字段 `file`）→ 拿到 `imagePath` 后随菜品新增 / 修改一起提交。
- 压缩与落盘分离：新增 `imaging/ImageCompressor` 只负责「Uri → 压缩字节」，采样缩放逻辑抽到 `imaging/Bitmaps` 供 `ImageStore` 与压缩器共用。
- 取舍：旧图片不在 M11 清理（换图 / 删菜后平板上的旧图仍占存储），与「手机端不做图片清理」的决策一致；接口面因此不新增 `DELETE /images`。

### 2.5 撤销语义

- 由「撤销本机最后一条卖出记录」改为「撤销该菜品全局最后一条卖出记录」：`SaleRecordDao.getActiveFor(dishId)` 不再按 `deviceId` 过滤，`UnsellPolicy.pickLastRevocable(records)` 取 `maxByOrNull { it.id }`。
- `deviceId` 参数与契约保持不变（`SellRequest.deviceId` 仍必填）：它继续作为卖出流水的归属信息，只是不再限制谁能撤销。
- 取舍：摊位上「谁卖错了谁撤」是最常见场景，但「老板在平板上撤掉手机刚卖的那一单」同样高频；统一为全局最后一条更符合实际，代价是多设备同时操作时可能撤到对方的那一单（摊位上可接受）。

### 2.6 恢复默认菜单

- 新增 `POST /api/v1/menu/reset`（204）：主机调用 `MenuRepository.resetToSeedMenu()`，仓储发出 `FullReload`，`HostServer` 按既有规则改为广播 `snapshot`，两端重新对齐。
- 与平板按钮的差异：平板的「恢复默认菜单」在本机执行并顺带清理孤儿图片；REST 路径不清理（与第 2.4 节一致）。

## 3. 接口与数据模型变化

- `GET /api/v1/state` 新增字段：`storeName`（String，店名，空表示未设置）、`clientEditsEnabled`（Boolean，手机是否可编辑）。
- 新增 `POST /api/v1/menu/reset`：无请求体；成功 204；需 `Authorization`，受第 2.3 节角色判定约束。
- 新增错误码 `forbidden`（HTTP 403）：主机拒绝手机写请求时返回，`message` 为中文提示。
- 请求头：新增 `X-Device-Id` 与 `X-Device-Role`（取值 `host` / `client`），仅主机用于开关判定，缺失视为不受限。
- `SettingsStore` 新增 `clientEditsEnabled`（默认 true）。
- 客户端 DTO：`StateDto` 增加上述两字段（可空带默认值，老客户端解析不受影响）；`ClientMenuState` 增加 `storeName` 与 `canEdit`。

## 4. 边界与失败场景

- 离线（未连上）：管理模式入口不可用；即使发出 `submit` 也直接失败并提示「离线状态下无法提交」。
- 提交期间断线：等待解除后按失败处理并提示，界面回到可编辑态，镜像保持最后一次同步结果。
- 开关在提交瞬间被关闭：主管线返回 403，手机提示「平板已关闭手机编辑」，自动拉一次 `/state` 以刷新可编辑态。
- 目标已被删除：主机返回 404 / 409，提示后解除禁用，随下一次广播重新对齐。
- 重复点击：提交期间按钮禁用；每次写请求都带唯一 `requestId`，即使重试也不会重复落库（主机 LRU 200 幂等回放）。
- 上传图片失败（解码失败 / 超过 10MB）：提示后菜品弹窗保留，可重试或改为无图提交。
- 图片体积：压缩后通常几百 KB，远低于主机 10MB 上限。
- 拒绝写请求后的连接可用性：403 在读取请求体之前判定，主机必须先按 `Content-Length` 丢弃请求体再响应；否则客户端复用同一条 keep-alive 连接时，残留字节会被解析成脏请求行（表现为「一次 403 之后该连接上的请求全部 400 语法错误」）。

## 5. 测试与验收

- JVM：`HostApiTest` 覆盖 `POST /menu/reset` → 204 与 `/state` 新字段；新增 `ClientCommandTest` 覆盖命令到请求的映射（`requestId` 唯一、`UpdateDish` 不携带 `soldOut` / `enabled`、`imagePath` 空串表示清空）；`SellPolicyTest` 的撤销语义用例改为跨设备可撤销；`MenuRepositoryTest` 补一条跨设备撤销用例（撤销掉的是对方那一单）。
- 仪表：`HostServerTest` 覆盖「带 `X-Device-Role: client` 的写请求在开关关闭时 403、GET 仍 200、host 角色不受限」与「`POST /menu/reset` → 204 且 WS 收到 `snapshot`」；`ClientSessionTest` 覆盖「改价 → 沽清 → 卖出 → 撤销 → 新增菜品 → 分类改名 / 新增 / 删除 → 上传图片 → 恢复默认菜单」与「离线提交失败」「开关关闭后提交 403」。
- 真机双机：手机改价平板 1 秒内同步；手机完成日常操作；平板关闭开关后手机提交被拒并提示、重开即恢复；恢复默认菜单两端一致显示 12 道菜。
- 验收命令：`:app:testDebugUnitTest :app:assembleDebug :app:connectedDebugAndroidTest` 全绿。

## 6. 实现位置与验证结果（M11，2026-10-07）

- 契约：`net/protocol/Contract.kt`（`StateDto` 新字段、`ErrorCode.FORBIDDEN`）；`net/protocol/DeviceRole` 复用现有 host / client 取值。
- 主机侧：`host/HostApi` 新增 `/menu/reset` 路由；`host/HostMessages.MenuBackend.resetMenu`；`host/RepositoryMenuBackend` 实现与 `state()` 新字段；`host/HostServer` 角色判定与 403、`broadcastStateNow()`；`host/HostStatusProvider` 开关读写与广播；`data/SettingsStore.clientEditsEnabled`；`ui/admin` 设置弹窗开关。
- 撤销：`data/db/SaleRecordDao.getActiveFor`、`domain/SellPolicy.UnsellPolicy`、`data/MenuRepository.unsell`。
- 客户端：`net/HostRestClient`（设备头 + 全部写方法与 `POST /images` 上传）、`client/ClientCommand`（命令与映射）、`client/ClientSession.submit/uploadImage`、`imaging/ImageCompressor` 与 `imaging/Bitmaps`。
- 界面：`ui/client/ClientMenuScreen`（管理模式、分类长按、行操作、新增菜品、恢复默认菜单、Snackbar）、`ui/client/ClientApp`、`ui/client/ClientSettingsDialog`；通用对话框迁到 `ui/dialogs/MenuDialogs.kt`，`ui/admin` 与 `ui/client` 共用。
- 实现中修复（仪表测试暴露，均已复验）：
  - `net/HostRestClient.uploadImage` 原用 OkHttp 默认的 `multipart/mixed`，而 NanoHTTPD 的 `ContentType.isMultipart()` 只认 `multipart/form-data`，导致上传恒返回「缺少 file 字段」400；改为 `MultipartBody.FORM`。
  - 403 拒绝发生在读请求体之前，客户端复用同一条 keep-alive 连接时残留字节被解析成脏请求行（`BAD REQUEST: ... HTTP verb {"name":...}PATCH unhandled`），表现为「一次 403 之后该连接上的请求全部 400」；现改为 `HostServer` 拒绝前先按 `Content-Length` 丢弃请求体。
- 验证：JVM 单测 139 项通过（新增 `ClientCommandTest` 9 项、`HostApiTest` 2 项）；平板仪表测试 53 项通过（Teclast T10 / Android 7.0）。

## 7. 未决事项

- 手机端备份导入导出（保留在平板，避免误操作）。
- 换图 / 删菜后的旧图回收（可在平板侧加「清理未引用图片」按钮，或新增 `DELETE /images/{name}` 并按引用计数校验）。
- 强身份约束的客户端 token 与按设备授权（需要改配对、存储与 WS 鉴权）。
- 扫码配对、NSD 自动发现、多主机切换。
