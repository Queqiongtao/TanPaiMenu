# 0001 菜单数据模型与接口契约

- 状态：草稿
- 对应阶段：Phase 1 / Phase 2
- 关联：`docs/architecture.md`（分层与模块、关键流程与数据流）、`docs/PLAN.md`（第 4、5 节）

## 1. 背景与目标

统一约定主机侧的 Room 数据模型与局域网 REST / WebSocket 契约，使平板端、手机端与测试脚本对同一份契约实现，避免到运行时才发现字段与语义不一致。

## 2. 数据模型

### 2.1 实体与字段

| 实体 | 字段 | 类型 | 约束 |
| --- | --- | --- | --- |
| `Category` | id | Long | 主键，自增 |
| | name | String | 1-20 字，非空白 |
| | sortOrder | Int | 升序排列，允许负值 |
| | enabled | Boolean | 默认 true |
| | updatedAt | Long | UTC epoch 毫秒 |
| `Dish` | id | Long | 主键，自增 |
| | categoryId | Long | 外键 → `Category.id` |
| | name | String | 1-20 字，非空白 |
| | priceCents | Int | 0-999999 |
| | unit | String | 0-6 字，默认「份」 |
| | imagePath | String? | 相对路径，可空 |
| | stockEnabled | Boolean | 默认 false |
| | stockCount | Int | ≥ 0，默认 0 |
| | soldOut | Boolean | 默认 false |
| | description | String | 0-100 字 |
| | sortOrder | Int | 允许负值 |
| | enabled | Boolean | 删除即置 false |
| | updatedAt | Long | UTC epoch 毫秒 |
| `SaleRecord` | id | Long | 主键，自增 |
| | dishId | Long | 允许指向已软删除菜品 |
| | qty | Int | 固定 1（本期不支持一次多份） |
| | createdAt | Long | UTC epoch 毫秒 |
| | deviceId | String | 发起设备标识，用于撤销归属 |
| | revoked | Boolean | 默认 false，撤销后置 true |
| `ConnectedDevice` | id | String | 设备标识（客户端首次连接生成 UUID 并持久化） |
| | name | String | 设备展示名 |
| | role | String | host / client |
| | lastSeen | Long | UTC epoch 毫秒，超过 30s 视为离线 |
| `AppMeta` | key | String | 主键 |
| | value | String | 其中 `version` 存放全局版本号 |

### 2.2 全局约定

- 主键：Room `@PrimaryKey(autoGenerate = true)`，REST 路径使用整数 id。
- 时间：库内存 UTC epoch 毫秒；JSON 传输 ISO-8601 UTC 字符串，例如 `2026-10-05T03:20:30.123Z`。
- 版本号：全局单调递增 `version` 存 `AppMeta`，每次写操作在同一事务内 +1；业务实体不再各自维护 version。
- 排序：列表按 `sortOrder` 升序，其次 `id` 升序。
- 软删除：`enabled = false` 的记录不出现在 `/state` 快照与列表中。

## 3. REST 契约（前缀 `/api/v1`）

### 3.1 通用

- 请求：`Content-Type: application/json`（图片上传除外）；除配对外均需 `Authorization: Bearer <token>`。
- 成功：2xx + JSON 实体；列表接口返回数组。
- 失败：统一 `{"error":{"code":"...","message":"中文提示"}}`。
- 时间字段：ISO-8601 UTC 字符串。

错误码表：

| HTTP | code | 场景 |
| --- | --- | --- |
| 400 | `invalid_argument` | 字段缺失、越界、格式错误 |
| 401 | `unauthorized` | token 缺失 / 错误 / 已失效 |
| 404 | `not_found` | id 不存在或已软删除 |
| 409 | `conflict` | 已沽清仍卖出、未启用库存仍卖出、无记录可撤销 |
| 413 | `payload_too_large` | 图片超过 10MB |
| 500 | `internal` | 未预期异常（响应附日志 id） |

### 3.2 幂等

- 所有写操作请求体可带 `requestId`（客户端生成的 UUID）。
- 主机保留最近 200 条 `requestId → 响应`；重复 `requestId` 直接返回首次结果，不重复执行。
- 未带 `requestId` 时按普通请求处理，不保证幂等。

### 3.3 接口明细

`GET /state`

- 响应：`{"version":12,"categories":[],"dishes":[]}`
- 语义：全量快照（仅 `enabled = true`）；客户端连接 / 重连首先调用。

`GET /categories`、`POST /categories`

- POST 请求：`{"name":"热菜","sortOrder":1,"requestId":"..."}`
- 响应：完整 `Category` 对象。

`PATCH /categories/{id}`、`DELETE /categories/{id}`

- PATCH 可改字段：`name`、`sortOrder`、`enabled`。
- DELETE：级联将其下菜品置 `enabled = false`；`SaleRecord` 保留。

`GET /dishes`、`POST /dishes`

- POST 请求：`{"categoryId":1,"name":"烤串","priceCents":300,"unit":"串","stockEnabled":true,"stockCount":20,"description":"","sortOrder":1,"requestId":"..."}`
- 强校验：见 2.1 约束；`categoryId` 必须存在且 `enabled = true`。

`PATCH /dishes/{id}`、`DELETE /dishes/{id}`

- PATCH 可改字段：`categoryId`、`name`、`priceCents`、`unit`、`imagePath`、`stockEnabled`、`stockCount`、`soldOut`、`description`、`sortOrder`、`enabled`。
- DELETE：置 `enabled = false`，并删除其图片文件。

`POST /dishes/{id}/sell`

- 请求：`{"deviceId":"...","requestId":"..."}`
- 语义：`enabled = false` → 404；`stockEnabled = false` 或 `soldOut = true` → 409；`stockCount` 减 1，减到 0 自动置 `soldOut = true`；写一条 `SaleRecord`。
- 响应：更新后的 `Dish`。

`POST /dishes/{id}/unsell`

- 请求：`{"deviceId":"...","requestId":"..."}`
- 语义：取该 `deviceId` 最近一条 `revoked = false` 的 `SaleRecord`；无记录 → 409；`stockCount` +1 并清除自动沽清，将该记录置 `revoked = true`。
- 响应：更新后的 `Dish`。

`POST /images`（multipart/form-data，字段名 `file`）

- 限制：`image/jpeg`、`image/png`，单张 ≤ 10MB。
- 处理：长边压到 ≤ 1280px，JPEG 质量 80，存 `filesDir/images/<uuid>.jpg`。
- 响应：`{"imagePath":"images/<uuid>.jpg","url":"/api/v1/images/<uuid>.jpg"}`

`GET /images/{name}`

- `name` 必须匹配 `^[0-9a-f-]{36}\.(jpg|png)$`，否则 404。
- 响应：图片字节流 + 对应 `Content-Type`。

`GET /devices`

- 响应：`[{"id":"...","name":"手机A","role":"client","lastSeen":"..."}]`；`lastSeen` 超过 30s 视为离线。

## 4. WebSocket 契约（`/ws`）

- 连接：`ws://<ip>:<port>/ws?token=<token>`；token 错误以关闭码 4401 断开。
- 首帧：`{"type":"snapshot","version":12,"payload":{}}`（payload 同 `/state`）。
- 后续事件：`{"type":"dish.updated","version":13,"payload":{}}`；类型取值 `dish.updated`、`dish.deleted`、`category.updated`、`category.deleted`、`device.joined`、`device.left`。
- 客户端规则：`version` 小于本地版本的事件直接丢弃，不做合并。
- 重连：断开后重新调用 `/state` 取全量快照；菜单 ≤ 30 道，不做增量补齐。

## 5. 测试与验收

- 契约测试覆盖 3.3 全部接口的正常与错误路径，逐条核对错误码表。
- 幂等：同一 `requestId` 重复 `sell`，余量只减一次。
- 序列化：实体与事件 JSON 往返一致，时间格式符合 ISO-8601 UTC。
- 校验：越界、空白名称、错误 MIME、超大图片均返回预期错误码。

## 6. 未决事项

- 是否支持一次卖出多份（`qty > 1`）：暂不支持，Phase 4 再评估。
- 撤销是否允许跨设备：暂按 `deviceId` 归属限制。
