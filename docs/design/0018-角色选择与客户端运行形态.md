# 0018 角色选择与客户端运行形态

- 状态：已实现（M10，2026-10-07）
- 对应阶段：Phase 3（M10）
- 关联：`docs/design/0019-手机客户端配对与只读浏览.md`、`docs/design/0002-局域网配对与同步.md`、`docs/design/0003-平板运行形态与门禁.md`、`docs/architecture.md`

## 1. 背景与目标

同一个 APK 既要当平板主机（摊位上长期驻留展示页），又要当手机客户端（随身改菜单）。此前应用只有「主机」一种形态：`App.onCreate` 无条件建库、导入默认菜单、启动前台服务，`MainActivity` 无条件进入沉浸式展示页。

目标：

1. 首次启动选择角色（平板主机 / 手机客户端），落盘持久化，设置里可改。
2. 两套运行形态互不干扰：主机保留既有 kiosk（沉浸、常亮、开机自启、PIN 门禁、前台服务）；客户端使用常规系统栏、不常亮、不自启、不建库、不启服务。
3. 升级兼容：老平板升级后 `role` 为空，首启多一次角色选择，既有数据与配置不变。

## 2. 方案设计（含取舍）

### 2.1 角色表示与默认值

- `data/Role.kt`：`enum class Role(key) { HOST("host"), CLIENT("client") }`。
- `SettingsStore.role`（偏好键 `role`）为 null 表示尚未选择；**不设默认值**，避免手机端被误判为主机（会建库、导默认菜单并启动前台服务）。
- 取舍：不用「屏幕尺寸自动判定」——手机横屏或小平板会误判，角色归属应由用户自己决定。

### 2.2 运行形态分流

| 关注点 | 平板主机 | 手机客户端 |
| --- | --- | --- |
| 入口界面 | `ui/TanPaiMenuApp`（展示页 + 长按进管理） | `ui/client/ClientApp`（扫码配对页 / 只读菜单页） |
| 相机 | 仅传图时经系统相机 | 未配对时用于扫配对二维码（M12，见 `0022`） |
| 系统栏 | 沉浸式隐藏 | 常规显示 |
| 屏幕常亮 | 展示页常亮 | 不常亮 |
| 开机自启 | 受「开机自启」开关控制 | 不响应 |
| 数据库与图片 | Room + `filesDir/images` | 不落库（内存镜像） |
| 前台服务 | `HostService` 保活主机服务 | 不启动 |
| 门禁 | 长按店名 2 秒 + PIN | 无（凭配对 token 授权） |

- `MainActivity` 读取 `SettingsStore.role` 并持有为 Compose 状态：null → `RoleSelectScreen`；HOST → 现有流程；CLIENT → `ClientApp`。切换角色即时重绘，并按角色重设系统栏。
- `App` 提供 `applyRole(role)`（落盘 + 启停前台服务）与 `enterHostMode()`（幂等初始化：seed 默认菜单、清理孤儿图、启动前台服务）。
- `App.onCreate` 只在 `role == HOST` 时执行主机初始化；`role == CLIENT` 或未选择时不做任何主机侧动作。
- `BootReceiver` 增加角色判断：非主机直接返回。

### 2.3 客户端不落库

客户端菜单数据只存在内存镜像（见 `0019`），因此 `AppContainer` 的 Room 实例在客户端形态下不会被访问，不会产生数据库文件；图片走 Coil 磁盘缓存。

## 3. 接口与数据模型变化

- 新增 `data/Role.kt`（枚举）与 `SettingsStore.role`（键 `role`，null = 未选择）。
- 新增 `SettingsStore.clientHostAddress`、`clientToken`、`clientDeviceName`（默认取 `Build.MODEL`）。
- 客户端形态新增扫码配对（`qrcode/` + `ui/client/QrScanView`，M12）；角色分流程与偏好键不变，见 `docs/design/0022`。
- 无协议变更（配对协议见 `0019`）。

## 4. 边界与失败场景

- 未选择角色：只显示角色选择页，不建库、不起服务。
- 切换角色：立即落盘；切到主机时启动前台服务并做一次主机初始化（幂等），切到客户端时停掉前台服务与客户端会话。
- 老版本升级：`role` 缺失 → 首启出现角色选择页，菜单、图片、PIN、配对码等既有数据全部保留。
- 客户端形态下不存在「读到本机旧菜单」的问题：客户端不读本机 Room。

## 5. 测试与验收

- JVM：数据层角色读写与客户端地址规范化（见 `0019` 第 5 节）。
- 仪表：角色选择写入 `role`；`App.applyRole` 切换时前台服务同步启停（沿用 `HostServiceTest` 的断言方式）。
- 真机：平板首启选「平板主机」，重启后自动进入展示页且服务常驻；手机首启选「手机客户端」，界面为常规系统栏、无常驻通知。

## 6. 实现位置与验证结果（M10，2026-10-07）

- 数据：`data/Role.kt`；`SettingsStore.role` / `clientHostAddress` / `clientToken` / `clientDeviceName` 与 `clearClientPairing()`。
- 装配：`App.onCreate` 按角色分流，`App.applyRole` / `App.enterHostMode`；`AppContainer` 新增 `pairCodeManager` / `clientRest` / `clientSockets` / `clientSession` / `pairingClient`；`App` 实现 `ImageLoaderFactory`，仅对主机地址的图片请求附加 `Authorization`。
- 界面：`ui/RoleSelectScreen.kt`、`ui/client/ClientApp.kt`；`MainActivity` 持有角色状态，切换时重设系统栏（主机沉浸、其余常规）；`kiosk/BootReceiver` 仅主机形态自启。
- 主机侧切换入口：管理页设置弹窗「切换为手机客户端」（二次确认，见 `ui/admin/AdminScreen.kt`）。
- 验证：平板仪表测试 47 项全绿（含客户端端到端 `ClientSessionTest`）；`role` 缺失时应用只打印「尚未选择角色」，不建库、不启服务（真机日志确认）。双机真机验收（平板 + 手机）待手机接入后执行。

## 7. 未决事项

- 客户端是否需要「作为第二块展示屏」（当前不做）。
- 手机端是否需要 PIN 二次保护（当前不做，沿用配对 token 授权）。
