# 0007 展示页背景图片

- 状态：已实现（2026-10-06）
- 对应阶段：Phase 1 修订（展示页外观）
- 关联：`docs/design/0006-展示页紧凑布局与默认菜单.md`、`docs/design/0004-图片处理与数据备份.md`、`docs/architecture.md`

## 1. 背景与目标

展示页此前只有纯色底。店主希望整屏背景可换成自己的图片（门店招牌、菜品实拍等），同时不能牺牲菜名与价格的可读性。

目标：

- 展示页支持自定义背景图，整屏铺满、按比例裁切，不留黑边、不拉伸变形。
- 图片上叠加可调白色蒙版（0%–80%，默认 30%），保证卡片文字在花哨图片上仍可读。
- 图片来源支持「相册选择」与「拍照」两条路径，入口在管理页设置弹窗。
- 未设置背景图时，展示页视觉与改动前完全一致（纯色底）。
- 背景图在应用重启的孤儿图清理与「恢复默认菜单」中不被误删。

## 2. 方案设计（含取舍）

### 2.1 存储与设置项

| 设置项 | key | 取值 | 默认 |
| --- | --- | --- | --- |
| 背景图相对路径 | `background_image` | `images/<uuid>.jpg` 或空 | 空（未设置） |
| 背景蒙版不透明度 | `background_scrim` | 0–80（百分比整数） | 30 |

- 复用 `ImageStore` 的 `images/` 目录与 UUID 命名，背景图与菜品图共用同一存储层，不新增目录或数据表。
- 蒙版上限 80%：再高基本只剩一层白，失去「看到背景图」的意义。

### 2.2 图片来源与压缩

- 相册：`ActivityResultContracts.GetContent("image/*")`。
- 拍照：`ActivityResultContracts.TakePicture()` + `CAMERA` 运行时权限，`FileProvider` 由 `ImageStore.newCaptureUri()` 生成，链路与菜品图完全一致（见 `ui/admin/AdminDialogs.kt`）。
- 背景图按长边 2048、JPEG 85 导入（`ImageStore.importFromUri(uri, maxEdge, jpegQuality)` 新增可选参数；菜品图默认仍为长边 1280 / 质量 80）。
- 取舍：1280 长边在 2560×1600 屏上铺满会明显发虚，故为背景图单独放宽到 2048；代价是单张约 0.5–1.5MB。

### 2.3 渲染分层

展示页根布局由单一 `Column` 改为 `Box` 三层：

1. 背景层：`AsyncImage(model = File(filesDir, path), contentScale = ContentScale.Crop)` 铺满整屏（含原先 `ContentPadding` 之外的外沿）。
2. 蒙版层：`Box(fillMaxSize().background(Color.White.copy(alpha = scrim)))`。
3. 内容层：原有 `Column(padding(ContentPadding))`（顶部条 + 网格），层次与代码保持不变。

未设置背景图或文件不存在时不渲染前两层，行为与改动前一致。

### 2.4 与卡片半透明的关系

- 卡片底色沿用「M3 默认卡片底 × `cardAlphaPercent`」，因此背景图会从半透明卡片后透出，属预期效果。
- 文字、徽标、缩略图不受背景影响；深色或高对比图片上可通过调高蒙版恢复可读性。

### 2.5 孤儿图保护（实现关键）

`App.onCreate` 启动时执行 `ImageStore.deleteOrphans(menuRepository.allImagePaths())`，只保留被菜品引用的图片。背景图不属于任何菜品，若不处理会在每次冷启动后被删除。

- 启动清理：引用集合改为「菜品图 ∪ `settingsStore.backgroundImagePath`」。
- 恢复默认菜单：`AdminViewModel.resetToDefaultMenu()` 同样以背景图路径作为保留项。
- 换图 / 清除：`AdminViewModel.applyBackgroundImage` / `clearBackgroundImage` 主动删除被替换的旧文件。

### 2.6 备份口径

- 背景图与蒙版不参与「导出备份 / 导入备份」，与店名、卡片不透明度一致；`backup.json` 仍为 `format 1`，结构不变。
- 后果：换机恢复后需重新设置背景图；导入备份不影响当前设备已有的背景图。

## 4. 边界与失败场景

| 场景 | 处理 |
| --- | --- |
| 未设置背景图 | 不渲染背景层，展示页与旧版一致 |
| 背景图文件被外部删除 | `File.exists()` 为假，同上，不崩溃 |
| 相册 / 拍照返回的图片无法解码 | `importFromUri` 返回 null，弹窗内提示「背景图读取失败，请重新选择」 |
| 未授予相机权限 | 提示「未授予相机权限，无法拍照」，可再次点击重新授权 |
| 换图 / 清除产生的旧文件 | 主动删除，避免残留 |
| 蒙版设为 0% | 原图直出，可读性由店主自行判断 |

## 5. 测试与验收

- 相册选择背景图 → 展示页整屏铺满裁切、无拉伸；拍照添加同样生效。
- 蒙版 0% / 30% / 80% 三档对比，卡片文字可读性随档位变化。
- 清除背景图后恢复纯色底；应用重启后已设置的背景图仍在。
- 「恢复默认菜单」后背景图仍在（不被孤儿清理误删）。
- 未设置背景图时与改动前一致。
