# 0013 展示页横竖屏与多尺寸自适应

- 状态：已实现（2026-10-06）
- 对应阶段：Phase 1 修订（展示页外观与设备适配）
- 关联：`docs/design/0006-展示页紧凑布局与默认菜单.md`、`docs/design/0012-展示页价格强调.md`、`docs/architecture.md`、`docs/device-baseline.md`

## 1. 背景与目标

展示页版式此前是按「T10 横屏 961.5dp × 553dp」逐值调优出来的：固定 2 列、卡片 68dp、缩略图 56dp、价格列 128dp、状态列 68dp、顶栏 72dp；Activity 用 `android:screenOrientation="sensorLandscape"` 锁死横屏。换一台设备、或把平板竖过来都会走样——竖屏 2 列时单卡只有约 280dp，而卡片内部固定部分（内边距 20 + 缩略图 56 + 图文距 8 + 价格列 128 + 状态列 68 + 两个列距 10）就要 290dp，菜名列（弹性列）会被压成 0 宽、行尾状态徽标被裁掉。

目标：

- 展示页横竖屏都可用：解除方向锁，跟随重力感应（`fullSensor`），不依赖系统「自动旋转」开关。
- 版式规则化：列数与卡片形态由运行时可用宽高推导，不再按设备写死；新设备自动落档，不需要改代码。
- T10 横屏版式与现状保持一致；T10 竖屏同样一屏可见 12 道菜。
- 保住远距可读性：竖屏不缩小菜名字号，改用「两行卡片」形态。
- 不改数据模型、备份格式、网络协议，不新增依赖。

## 2. 方案设计（含取舍）

### 2.1 为什么是「规则」而不是「按设备写死」

按机型写死（`if 设备 == T10`）无法覆盖新硬件；按屏幕比例整体缩放会把字号缩到不可读。改为：**列数由「单卡最小宽度」反推、卡片形态由单卡实际宽度决定、尺寸集中到一个规格对象**，纯函数推导，可在 JVM 单测里穷举验证。

### 2.2 选档规则

输入为网格区域的实际可用宽高（dp），列距固定 16dp，候选列数 1–4：

1. 单行档：取最大列数使单卡宽 ≥ 380dp；若该档可见菜品数 ≥ 12 → 采用单行档。
2. 否则两行档：取最大列数使单卡宽 ≥ 240dp；若该档可见菜品数 ≥ 12 → 采用两行档。
3. 两者都放不下（如手机竖屏）→ 取「可见菜品数更多」的档，平手取单行档（字大优先），允许滚动。

其中可见行数 = `floor((可用网格高 + 行距) / (卡高 + 行距))`。「12 道」是**固定选档基准**，不随分类实际菜品数变化，保证同一台设备上版式稳定、不因菜单增减而跳档。

落档示例（同时是 `DisplaySpecTest` 的用例）：

| 场景 | 可用网格宽 × 高 | 结果 |
| --- | --- | --- |
| T10 横屏 | 937.5 × 497dp | 单行档 2 列，可见 12 道 |
| T10 竖屏 | 577 × 821dp | 两行档 2 列，可见 12 道 |
| 手机竖屏 | 411 × 708dp | 单行档 1 列，可见 9 道（滚动） |
| 宽屏平板 | 1400 × 600dp | 单行档 3 列 |
| 极窄屏 | 宽 < 240dp | 两行档 1 列（压缩兜底，不崩） |

### 2.3 两行卡片

竖屏单卡约 280dp，一行放不下「缩略图 + 菜名 + 价格 + 徽标」而不缩字号，所以窄卡改为两行：上行「缩略图 + 菜名」，下行「价格胶囊 + 状态徽标」。

- 缩略图与单行档同尺寸（56dp）：店主希望竖屏菜品图与横屏一样大，两档共用同一常量，卡片高度随之由 96dp 增到 120dp（上下内边距 16 + 缩略图 56 + 行距 8 + 价格行约 37 + 余量）。
- 价格数字 20sp / 单位 12sp、胶囊最小宽 72dp；下行价格胶囊 `weight(1f, fill = false)` + 状态徽标，超长价格仍有省略号兜底。
- 售完灰化规则不变（整块内容 `alpha 0.45`）；价格仍用 `PriceColors` 胶囊底 + 喜庆红字。

### 2.4 尺寸表

| 项 | 单行档（单卡 ≥ 380dp，= 现状） | 两行档（单卡 ≥ 240dp） |
| --- | --- | --- |
| 卡片形态 | 单行三列：缩略图 / 菜名 / 价格 / 状态 | 两行：上行缩略图 + 菜名；下行价格 + 状态 |
| 卡高 / 内边距 | 68dp / 横 10dp、纵 6dp | 120dp / 横 8dp、纵 8dp |
| 缩略图 / 图文距 | 56dp / 8dp | 56dp（与单行档一致）/ 8dp |
| 菜名 | 22sp（titleLarge），超宽跑马灯 | 22sp，超宽跑马灯 |
| 价格 | 定宽列 128dp、胶囊最小 96dp、数字 22sp / 单位 13sp | 自适应宽、胶囊最小 72dp、数字 20sp / 单位 12sp |
| 状态 | 定宽列 68dp、徽标 14sp | 自适应宽、徽标 12sp |
| 卡内列距 | 5dp | 8dp |
| 网格列距 / 行距 / 内容内边距 | 16dp / 12dp / 12dp | 16dp / 12dp / 12dp |

### 2.5 顶栏

顶栏尺寸按顶栏可用宽分档（阈值 720dp）；店名仍沿用「超 6 字降档」规则。

| 项 | 宽档（≥ 720dp，= 现状） | 窄档（< 720dp） |
| --- | --- | --- |
| 顶栏高 / 招牌高 | 72dp / 68dp | 60dp / 52dp |
| 店名字号（行高） | 48sp（56sp），超 6 字 36sp（44sp） | 32sp（40sp），超 6 字 26sp（32sp） |
| 店名限宽 | min(320dp, 40% 顶栏宽) | min(240dp, 40% 顶栏宽) |
| 二维码入口 | 小码 56dp + 「加微信」13sp | 小码 48dp + 「加微信」12sp |
| 分类胶囊字号 | 16sp | 14sp |

### 2.6 取舍

- 不追求竖屏塞进更多列：列数受最小单卡宽约束，宁可滚动也不挤成不可读。
- 两行卡片要多一套实现，换来竖屏字号不缩；优于「单行整体缩小」。
- 管理页只做「不破版」级适配（侧栏宽度自适应 + 窄屏菜品行改两行），不重设计。

## 3. 接口与数据模型变化

| 位置 | 变化 |
| --- | --- |
| `ui/display/DisplaySpec.kt` | 新增：`DishCardLayout`（`SingleRow` / `TwoRow`）、`DisplaySpec`、`TopBarSpec`、纯函数 `displaySpecFor(width, height)` 与 `topBarSpecFor(width)` |
| `ui/display/DisplayScreen.kt` | 随尺寸变化的版式常量移入规格对象（圆角、内边距等两档一致者保留原处）；新增两行卡片实现；顶栏与网格改用 `BoxWithConstraints` 取实际宽高 |
| `ui/admin/AdminScreen.kt` | 侧栏宽度由固定 320dp 改为自适应；窄屏菜品行改上下两行 |
| `AndroidManifest.xml` | Activity `screenOrientation`：`sensorLandscape` → `fullSensor` |

无数据模型、备份格式、网络协议变化；`PriceFormatter` 输出契约不变；`DishCard` 的既有具名参数调用保持兼容（新增 `spec` 参数带默认值）。

## 4. 边界与失败场景

| 场景 | 处理 |
| --- | --- |
| 竖屏 | 两行档 2 列，菜名 22sp 不缩，价格胶囊与状态徽标在第二行 |
| 手机等很窄的竖屏 | 单行档 1 列（字大），12 道需要滚动；属屏幕物理限制 |
| 宽度 < 240dp | 两行档 1 列兜底，不崩、不重叠 |
| 分类菜品数不足 12 | 档位不变（12 是固定基准），只是行数更少 |
| 超长菜名 | 沿用跑马灯滚动，不换行、不撑破卡片 |
| 超长价格（`¥9999.99 / 份`） | 单行省略号，不撑破卡片 |
| 售完 | 卡片内容整体 `alpha 0.45`，价格胶囊与状态徽标一起变淡 |
| 旋转（含 180° 翻转） | Activity 重建，`selectedCategoryId` 由 `rememberSaveable` 保留，不回到第一个分类 |
| 管理页窄屏 | 侧栏 `min(320dp, 40% 宽)`，菜品行改两行 + 操作按钮横向可滚动 |

- 真机（Teclast T10）：横屏 12 道一屏、版式与改动前一致；竖屏 2 列两行、12 道一屏、菜名完整不跑马灯、无裁切重叠；旋转过程与转回横屏无残留；竖屏进管理页不裁切。
- 门禁：`assembleDebug` + `testDebugUnitTest` + `connectedDebugAndroidTest` 全绿。

## 6. 验证记录

- 构建与单测：2026-10-06，`assembleDebug`、`testDebugUnitTest` 通过；新增 `DisplaySpecTest` 7 项覆盖 §2.2 落档表与顶栏分档。
- 仪表测试：Teclast T10（API 24）`connectedDebugAndroidTest` **24 项全通过**，含新增的两行卡片 2 项（菜名 + `¥10 / 份` + 状态徽标同屏可见；售完徽标）。
- 真机横屏（T10）：与改动前逐像素一致——价格胶囊行 y=290/503/716/929/1142/1355、首行胶囊 x=697..952、「有货」徽标 x=1073..1145，12 道一屏无滚动。
- 真机竖屏：用临时 `sensorPortrait` 构建截图验证（正式包为 `fullSensor`，现场跟随重力感应）——2 列两行卡片、6 行 12 道一屏；行距实测 108.2dp（= 卡高 96 + 行距 12）；菜名 6 字完整显示、不走跑马灯；无裁切重叠；紧凑顶栏生效。
- 小屏横屏：`wm size 1900x1200`（应用区约 713×402dp）下自动降为 1 列单行、卡片全宽、价格与徽标对齐、无裁切（12 道滚动）——换尺寸不改代码即可落档。
- 2026-10-06 缩略图复测：两行档缩略图改 56dp 后，真机竖屏截图实测缩略图 ≈56dp（149px @ density 426），与横屏一致；6 行 12 道仍一屏、无裁切；`DisplaySpecTest` 新增「竖屏与横屏缩略图同尺寸」断言并通过。
- 未覆盖：管理页竖屏截图。该机未设管理密码，长按店名会先弹「设置管理密码」，为避免改动店主设备状态未继续；其窄屏兜底（侧栏 `min(320dp, 40%)`、菜品行两行 + 按钮横向滚动）只做了代码与尺寸推算确认。

## 7. 未决事项

- 是否需要给店主一个「固定横屏」开关（有些摊位用支架，不希望被误碰转屏）。
- 是否需要在竖屏进一步利用富余高度（例如把卡片放高、字号加大）。
