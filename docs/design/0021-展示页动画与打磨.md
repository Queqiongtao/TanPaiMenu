# 0021 展示页动画与打磨

- 状态：已实现（Phase 4，2026-10-07）
- 对应阶段：Phase 4
- 关联：`docs/PLAN.md` 第 6 节 Phase 4、`docs/design/0013-横竖屏与多尺寸自适应.md`、`docs/design/0014-默认菜品图片.md`、`docs/architecture.md`

## 1. 背景与目标

展示页当前已经完成布局、背景、价格与库存状态表达，但菜品之间缺少经营语义上的视觉重点，沽清、空闲滚动与启动过程也都是静态切换。Phase 4 的目标是在不破坏 Android 7 平板性能门禁的前提下，补齐四类打磨：

1. 菜品支持单选标签「推荐 / 新品」，在展示页缩略图上显示醒目标识。
2. 菜品从有货变为售完时，行尾「已售完」徽标播放一次盖章动画；静态版式与现有状态列一致。
3. 菜品超出当前屏容量时，长时间无操作后轻量自动滚动；任何触摸或手动滚动都会重置等待。
4. 应用启动过程不增加额外等待；启动动画只在性能门禁通过时启用，否则保持静态首屏。

所有动画只使用 `alpha` / `scale` / `translation`，不使用模糊、大面积阴影或每帧图片解码。任何效果不达标时按 `docs/PLAN.md` 第 8 节回退为静态。

## 2. 数据与契约变化

### 2.1 菜品标签

新增 `DishHighlight` 枚举：

| 值 | 契约值 | 展示 |
| --- | --- | --- |
| `Recommended` | `recommended` | 缩略图左上角「推荐」徽标 |
| `New` | `new` | 缩略图左上角「新品」徽标 |

`Dish.highlight: DishHighlight?`，`null` 表示无标签。标签是经营语义，不参与库存扣减或卖出逻辑。

### 2.2 数据库迁移

数据库版本从 2 升到 3，新增 `dish.highlight TEXT` 可空列。迁移只执行：

```sql
ALTER TABLE dish ADD COLUMN highlight TEXT
```

旧数据迁移后为 `null`，不改变默认菜单与既有菜单的展示。

### 2.3 REST / WS

- `DishDto` 增加 `highlight`，可空，默认 `null`。
- `DishCreateRequest` 增加 `highlight`，可空；手机端创建菜品时可带标签。
- `DishPatchRequest.highlight` 使用字符串三态：`null` 不修改，空串清空，`recommended` / `new` 设置标签。与 `imagePath` 的空串清空语义一致，避免 PATCH 无法区分「不修改」与「清空」。
- `RepositoryMenuBackend` 对非法标签返回 `invalid_argument`；客户端不会发送非法值。
- `ClientCommand.DishDraft` 增加标签字段，创建与修改请求均携带；旧客户端不带该字段时保持 `null`。

### 2.4 备份

`BackupDish` 增加可空 `highlight`，备份格式从 1 升到 2：

- 新版本可读取格式 1（字段缺省为 `null`）与格式 2。
- 旧版本读取格式 2 会因 `format > 支持上限` 拒绝，避免静默丢字段。
- 导入时仍沿用现有覆盖语义。

## 3. 交互与视觉设计

### 3.1 标签编辑

- `DishEditDialog` 增加一组三态选择：无 / 推荐 / 新品，不增加弹窗层级。
- 平板管理页与手机客户端共用现有弹窗，因此两端的编辑能力一致。
- 展示页只在缩略图左上角叠加小块徽标；没有图片时仍显示在首字占位图上。

### 3.2 沽清盖章

`DishCard` 监听到 `dish.soldOut` 由 `false` 变为 `true` 时，在状态列现有位置播放一次约 320ms 的进入动画：缩放从 1.18 收到 1.0，透明度从 0.2 升到 1.0。动画结束后保留现有静态「已售完」徽标，不覆盖菜名、不动价格列。

理由：此前已经明确不使用居中大印章，避免遮挡菜名；这里只让行尾状态徽标产生“盖章”感，兼顾可读性与改动最小。

### 3.3 空闲自动滚动

- 设置项「空闲自动滚动」默认开启。
- 仅当网格存在超出首屏的菜品时启用。
- 连续 15 秒无触摸、无滚动后，每 6 秒滚动一行的距离；到底部后回到第一行。
- 用户触摸、手动滚动、切换分类或菜单变更时取消当前等待并重新计时。
- 关闭开关后完全停在当前位置，不启动协程滚动。

该方案比图片轮播更轻量：不额外解码大图，不改变菜品点击区域，也不会让顾客在浏览时看到图片突换；明确不采用自动轮播作为本期实现。

### 3.4 启动过渡（验收后回退）

初版使用整页 `AnimatedVisibility` 淡入约 300ms。60 菜品同条件滚动测量未获得稳定收益，按性能门禁“不达标即回退”的要求，最终实现不保留整页淡入层，启动直接显示静态页面；`App.onCreate`、数据库初始化与主机服务启动路径保持不变。

## 4. 边界与失败场景

- 旧备份无 `highlight`：按 `null` 导入。
- 未知标签：拒绝请求，不写库；展示逻辑不会因未知值崩溃。
- 数据库迁移失败：沿用 Room 启动失败路径，不吞异常；迁移测试覆盖 2 → 3。
- 售完状态首次进入屏幕：按静态徽标显示，不播放“从有货变售完”的动画，避免滚动时形成无意义闪动。
- 自动滚动执行中用户触摸：立即停止，重置空闲计时。
- 分类菜品数量不足以滚动：不启动计时协程。
- 动画不影响 `KeepScreenOn`、长按店名进管理、二维码浮层与背景设置。

## 5. 测试与验收

- JVM：标签 DTO 往返、PATCH 空串清空、备份格式 1 / 2 兼容、展示规格与自动滚动阈值测试。
- 仪表：数据库 2 → 3 迁移保留旧菜品；菜品标签 UI 出现；售完动画的静态最终状态、自动滚动开关可用。
- 真机：60 菜品数据集下与未改基线同脚本对照；无操作等待后出现轻量滚动，触摸后立即停止。
- 回归：无标签、无库存菜品、售完菜品和横竖屏两种卡片布局均不溢出、不遮挡菜名。

## 6. 实现位置与验证结果（Phase 4，2026-10-07）

- 数据：`data/db/DishHighlight.kt`、`data/db/Entities.kt`、`TpDatabase.MIGRATION_2_3`、`SeedMenu`；Room schema 3 已导出。
- 契约：`net/protocol/Contract.kt` 与 `Mapping.kt` 增加 `highlight`；`DishPatchRequest.highlight` 三态由 `HostApi` / `RepositoryMenuBackend` 校验并落库。
- UI：`ui/dialogs/MenuDialogs.kt` 提供无 / 推荐 / 新品三态；`ui/display/DisplayScreen.kt` 渲染标签与盖章动画；`AutoScrollPolicy.kt` 负责滚动策略；`SettingsStore.autoScrollEnabled` 可在平板设置中关闭。
- 备份：`BackupFormat.FORMAT = 2`，`BackupDish.highlight` 可空；format 1 无该字段时按 `null` 读取。
- 验证：JVM 单测 147 项通过；Teclast T10（Android 7.0）仪表测试 56 项通过；Room 2→3 迁移保留旧菜品并将 `highlight` 置 null；展示页截图确认标签不遮挡菜名 / 价格。
- 性能：冷启动 `ThisTime=522ms`、`WaitTime=537ms`。60 菜品当前批处理滚动 p50 12ms / p95 22–26ms；同脚本未改基线 p50 12ms / p95 27ms，Phase 4 无相对回退。原始门禁记录为 p50 8ms / p95 16ms，后续发版需在同一脚本、同一设备温度和数据集下复测；启动整页淡入已回退为静态。

## 7. 未决事项
