# 0015 主机服务接口实现（M7）

- 状态：已实现（M7，含 M8 的配对信息展示）
- 对应阶段：Phase 2（M7，含 M8 的配对信息展示）
- 关联：`docs/design/0001-菜单数据模型与接口契约.md`、`docs/design/0002-局域网配对与同步.md`、`docs/architecture.md`

## 1. 背景与目标

M6 已交付契约 DTO、ISO-8601、实体映射与单写者事件流；M7 要在平板上把契约真正跑起来：局域网 REST `/api/v1/*` + WebSocket `/ws`、Bearer 鉴权、`requestId` 幂等、设备注册表与库迁移 1→2，并让店主能在管理页设置弹窗看到配对信息（地址 / 端口 / 配对码 / 二维码）。

范围边界：M7 不含前台服务保活、开机恢复、在线设备列表 UI（属 M8），也不含手机客户端（Phase 3）。

## 2. 方案设计（含取舍）

### 2.1 分层：纯 Kotlin 管线 + 薄适配层

| 层 | 职责 | 是否依赖 Android |
| --- | --- | --- |
| `net/protocol/` | 契约 DTO、事件类型、错误码、ISO-8601、实体映射 | 否（M6 已就绪） |
| `host/HostApi.kt` | 路由、鉴权、幂等、校验、错误映射、业务调用 | 否（可在 JVM 单测） |
| `host/HostServer.kt` | NanoHTTPD 适配：HTTP ↔ `HostRequest`/`HostResponse`、multipart、`/ws` | 是（网络与 `Context`） |
| `host/HostInfo.kt` | 取局域网 IPv4、拼配对地址与二维码内容 | 否（取 IP 的部分依赖 Android） |

取舍：把请求管线与 HTTP 容器解耦，M7 的主要逻辑可以用纯 JVM 单测覆盖（假 `MenuBackend`），NanoHTTPD 只做搬运；避免了「起真服务器才能测」的高成本。

### 2.2 请求管线

`鉴权 → requestId 幂等查表 → 参数校验 → 单写者执行 → 事务提交 → 广播事件 → 返回响应`（`docs/design/0002` 第 6.3 节）。

- 业务调用经窄接口 `MenuBackend`（`state/categories/dishes/sell/unsell/images` 等挂起方法），实现由 `MenuRepository` + `ImageStore` 提供，便于替换为测试替身。
- 幂等：内存 LRU 保留最近 200 条 `requestId → (status, body)`；命中直接回放，不重复执行；未带 `requestId` 不做幂等。
- 错误映射：`invalid_argument` 400、`unauthorized` 401、`forbidden` 403、`not_found` 404、`conflict` 409、`payload_too_large` 413、`internal` 500（响应体附带日志 id，同时写 `TpLog`）。
- 业务异常（`SellResult.Failure`）在管线内映射为 404/409，不抛出到容器。
- 非鉴权端点：`POST /pair`（一次性配对码换 token，M10）与 `POST /images` 的 multipart 一样，由传输层在统一鉴权管线之外分流到 `HostApi.handlePair`；`/pair` 自身校验配对码格式与 `deviceId`，错误映射为 400 / 401（锁定时 message 含剩余秒数），详见 `docs/design/0019`。
- 「允许手机编辑」判定（M11）：`HostServer.handleHttp` 在进入管线前拦截「写方法 + `X-Device-Role: client` + 开关关闭」的请求并返回 403 `forbidden`；`/pair` 与 GET 不受限。拒绝前先按 `Content-Length` 读掉请求体，否则残留字节会污染同一条 keep-alive 连接上的后续请求（表现为一次 403 之后该连接上的请求全部报 400 语法错误）。见 `docs/design/0020` 第 2.3 节。
- 新增路由（M11）：`POST /menu/reset` → 204，转 `MenuBackend.resetMenu()`；仓储发出 `FullReload`，传输层按既有规则改广播 `snapshot`（`docs/design/0020` 第 2.6 节）。

### 2.3 线程与阻塞

NanoHTTPD 在自己的工作线程回调，管线是挂起函数，用 `runBlocking` 就地等待；不涉及主线程，也不引入额外调度器。WS 广播订阅 `MenuRepository.events`，在主机侧协程作用域内消费并推给各连接。

请求体不依赖 NanoHTTPD 的 `parseBody`（其无 charset 时按 US-ASCII 解码、且只解析 POST/PUT）：统一按 `Content-Length` 读原始字节并以 UTF-8 显式解码，保证中文分类名与菜名正确落库。

### 2.4 图片通道

- `POST /images`：multipart 字段 `file`，仅 `image/jpeg`、`image/png`，≤10MB（超出 413）；转交 `ImageStore.importFromBytes`（复用「采样缩放 → 长边 ≤1280 → JPEG 质量 80」），返回 `{"imagePath":"images/<uuid>.jpg","url":"/api/v1/images/<uuid>.jpg"}`。
- 客户端必须发 `Content-Type: multipart/form-data`：NanoHTTPD 的 `ContentType.isMultipart()` 按该值精确匹配（`; boundary=...` 之外的参数会被剥离），发成 `multipart/mixed` 会被当成整块请求体，直接返回「缺少 file 字段」。
- `GET /images/{name}`：`name` 必须匹配 `^[0-9a-f-]{36}\.(jpg|png)$`，否则 404；命中返回字节流与对应 `Content-Type`。

### 2.5 WebSocket

- 连接：`ws://<ip>:<port>/ws?token=<token>&deviceId=<id>&name=<名称>&role=<client|host>`；`token` 必填，错误以关闭码 4401 断开；`deviceId`/`name`/`role` 可选，缺省用随机 id、名称「未命名设备」、角色 `client`。
- 首帧：`{"type":"snapshot","version":N,"payload":<同 /state>}`；后续帧来自 `MenuChange`：`dish.updated`/`dish.deleted`/`category.updated`/`category.deleted`；整库替换发 `snapshot`。
- 设备事件：连接建立 upsert `connected_device` 并广播 `device.joined`；断开更新 `lastSeen` 并广播 `device.left`。

### 2.6 设备注册表与库迁移

- 新增表 `connected_device(id TEXT PK, name TEXT, role TEXT, lastSeen INTEGER)`；`GET /devices` 返回全表，`lastSeen` 超过 30s 由客户端/UI 视为离线。
- 库版本 1 → 2：`Migration(1, 2)` 仅 `CREATE TABLE`，不触碰既有数据；导出 schema 提交为 `app/schemas/.../2.json`。

### 2.7 启动、端口与配对信息

- 服务在 `App.onCreate` 的 IO 协程中自启（平板即主机角色），把地址、端口、配对码写入 `TpLog` 便于排障。
- 端口：偏好存 `SettingsStore.serverPort`（默认 8080），绑定失败依次顺延 8081、8082；实际端口由 `HostServer` 暴露给 UI，不用实际值覆盖偏好。
- 配对码：`SettingsStore.pairToken`（首次读取生成 32 字节随机十六进制）；设置页「手机控制端」区块显示状态、`http://<ip>:<port>`、配对码、二维码（内容 `http://<ip>:<port>/#pair=<token>`，zxing 生成）与「更换配对码」（二次确认，立即生效并踢掉现有连接）。
- IP 获取：优先 `ConnectivityManager.activeNetwork` → `LinkProperties.linkAddresses` 的首个非回环 IPv4，兜底 `WifiManager.connectionInfo.ipAddress`；都拿不到时显示「未连接 Wi-Fi」。

## 4. 边界与失败场景

- 端口被占用：顺延绑定；全失败时设置页显示「服务未启动」，不影响平板本机使用。
- 无 Wi-Fi / 仅蜂窝：`http://<ip>` 显示为不可用提示，服务仍在监听。
- token 错误或已失效：REST 401；WS 以 4401 断开，客户端下次请求被拒。
- 请求体非法 JSON：400 `invalid_argument`，不进入单写者。
- 图片超限 / 非 jpeg、png：413 / 400，不落盘。
- 500：响应带日志 id，日志内含路径与异常栈，便于现场排障。
- 进程被杀：M7 只保证应用存活期间服务可用，保活策略属 M8。

## 6. 实现位置与验证结果

- 请求管线：`host/HostApi.kt`（路由、鉴权、幂等 LRU 200、参数校验、错误码映射）。
- 业务窄接口与实现：`host/HostMessages.kt`（`MenuBackend`、`HostRequest`/`HostResponse`、`WriteResult`、`ImagePayload`）、`host/RepositoryMenuBackend.kt`。
- 传输适配：`host/HostServer.kt`（NanoWSD 子类：HTTP ↔ 管线、multipart 取 `file`、端口顺延、4401 关闭帧、PATCH 请求体兜底）、`host/WsHub.kt`（连接注册表、事件帧构造与广播）。
- 配对信息：`host/HostInfo.kt`（局域网 IPv4、`http://<ip>:<port>`、二维码内容与 zxing 位图）、`host/HostStatus.kt`（UI 只读运行态与更换配对码）。
- 数据层：`data/db/Entities.kt` 的 `ConnectedDevice`、`data/db/DeviceDao.kt`、`TpDatabase` v2 + `MIGRATION_1_2`；`data/SettingsStore.kt` 的 `pairToken` / `serverPort`；`ImageStore.importFromBytes`。
- 装配与 UI：`App.kt`（`AppContainer` 组装 + `App.onCreate` 启动服务并写 `TpLog`）、`ui/admin/AdminViewModel.kt`、`ui/admin/AdminScreen.kt` 设置弹窗「手机控制端」区块、`res/values/strings.xml`。
- 与设计的差异（实现约束导致，语义不变）：
  - NanoHTTPD 2.3.1 的 `parseBody` 只解析 POST / PUT，且无 charset 时按 US-ASCII 解码会损坏中文：请求体统一由容器按 `Content-Length` 读原始字节并按 UTF-8 显式解码（`HostServer.readRawBody`），无长度时才退回 `parseBody`。
  - NanoWSD 的 `CloseCode` 枚举不含自定义码，4401 关闭帧按协议手工构造（2 字节大端码 + UTF-8 原因）；WS 鉴权在握手后立即关闭，REST 仍返回 401。
  - multipart 分区头不暴露 Content-Type，图片类型改由文件魔数判定（JPEG / PNG）。
- 验证（2026-10-06，Teclast T10 / Android 7.0）：
  - JVM 单测新增 29 项：`host/HostApiTest` 18、`host/WsHubTest` 7、`host/HostInfoTest` 4；全量 JVM 单测 86 项通过。
  - 仪表测试新增 10 项：`host/HostServerTest` 9（真实 HTTP 与裸 Socket WS 往返：鉴权、`/state`、`POST /dishes` 幂等、`PATCH`、卖出/撤销、`/devices`、图片上传与读取、WS 首帧与 `dish.updated`、错误 token 收到关闭帧）、`data/db/TpDatabaseMigrationTest` 1（1→2 迁移保留菜单并新增设备表）。
  - 平板 `connectedDebugAndroidTest` 41 项全绿。
- 真机验证（2026-10-06，Teclast T10 / Android 7.0，`adb forward tcp:8080 tcp:8080` + `curl`）：
  - 鉴权与读取：无 token 返回 401；带 `Authorization: Bearer <pairToken>` 时 `/state` 返回快照、`/devices` 返回 `[]`。
  - 中文写入（UTF-8 修复后复验）：`POST /api/v1/categories`（`--data-binary @utf8.json`）返回 `{"id":2,"name":"测试·烤韭菜",...}`；`PATCH /categories/2` 改名同样正确；随后 `DELETE /categories/2` 返回 204；`/state` 全程中文正常，无乱码。
  - 幂等与错误码：同 `requestId` 重复请求回放相同响应；不存在资源 404、非法参数 400、重复冲突 409。
  - UI：展示页 12 道默认菜品与价格正常；设置弹窗「手机控制端」显示「服务运行中」、`http://192.168.51.177:8080`、配对码、可扫描二维码与「更换配对码」。

## 7. 未决事项

（M10 追加）扫码配对与 `NsdManager` 自动发现未做，接入方式为「地址 + 6 位配对码」手输，见 `docs/design/0019` 第 6 节。

- 手机端是否在 token 之外再加 PIN（沿用 `0002`：默认不加）。
- 是否支持平板开热点作为发现兜底（沿用 `0002` 未决）。
