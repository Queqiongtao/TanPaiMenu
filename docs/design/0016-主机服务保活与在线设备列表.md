# 0016 主机服务保活与在线设备列表（M8）

- 状态：已实现（M8）
- 对应阶段：Phase 2（M8）
- 关联：`docs/design/0002-局域网配对与同步.md`（第 6.5 节）、`docs/design/0015-主机服务接口实现.md`、`docs/architecture.md`

## 1. 背景与目标

M7 已交付局域网 REST / WS、鉴权与幂等、设备注册表与配对信息展示，但服务端由 `App.onCreate` 的 IO 协程直接启动，**没有前台服务**：进程被系统回收或应用退到后台后，手机就再也连不上平板。同时设置页只有配对信息，看不到「现在有哪几台手机连着」。

M8 的目标：

1. 用前台服务保活主机服务端，避免息屏 / 退到桌面后被回收，并提供常驻通知。
2. 设置页新增「启用手机控制端」开关（默认开），关闭即停监听、断开已有连接、移除通知。
3. 设置页展示**当前在线设备列表**（只读、只显示在线）。

范围边界：不含手机客户端（Phase 3），不含设备踢出 / 全部断开操作，不含离线历史设备列表。

## 2. 方案设计（含取舍）

### 2.1 服务归属：前台服务拉起、`App` 持有实例

- `host/HostService.kt`：前台服务只负责「保活 + 通知」，`onStartCommand` 中先建通知渠道并 `startForeground`，随后调用 `App.ensureHostServerStarted()` 幂等地启动服务端。
- 服务端实例仍存放在 `AppContainer.hostServer`，`HostStatusProvider` 的读取路径不变（UI 仍只通过 `HostStatusProvider` 观察运行态）。
- 取舍：把「创建服务器实例」留在 `App`、把「常驻」交给服务，避免服务与容器互相持有；同时保持 M7 的 UI 依赖方向不变。

### 2.2 启动与停止

| 时机 | 行为 |
| --- | --- |
| 进程启动且 `hostEnabled` 为真 | `App.onCreate` 调用 `HostService.start(this)`，由服务 `startForeground` 后启动服务端 |
| 用户在设置页关闭开关 | `HostService.stop(this)`：服务 `onDestroy` → 停监听、以 1001 关闭全部 WS、移除通知 |
| 用户在设置页打开开关 | 立即 `HostService.start(this)`，无需重启应用 |
| 系统回收进程（`START_STICKY`） | 服务重建 → 再次 `startForeground` 并恢复监听 |

- 开机自启仍沿用既有逻辑（`BootReceiver` 拉起主界面 → 进程启动 → 服务启动）；「开机自启」关闭时，服务只在应用被打开后启动，本次不改该行为。
- 服务端启动时调用 `DeviceDao.deleteStale(now - 7 天)` 清理过期设备记录，避免 `connected_device` 无限增长。

### 2.3 常驻通知

- 渠道：id `host_service`、名称「手机控制端」、重要级别 `LOW`（无声音、不弹横幅），仅在 API 26+ 创建。
- 内容：标题为店名，正文为 `手机控制端运行中 · http://<ip>:<port>`；无 Wi-Fi 时为「未连接 Wi-Fi」，端口全部被占用时为「服务未启动」。
- 点击打开主界面（`PendingIntent` 指向 `MainActivity`，`FLAG_IMMUTABLE`）。
- `onStartCommand` 内启一个 30 秒周期的协程刷新通知文本，覆盖 Wi-Fi 地址变化；服务销毁时随作用域取消。
- 小图标使用新增的单色 vector `res/drawable/ic_host_service.xml`（工程此前没有任何图标资源）。

### 2.4 在线设备列表

- 数据源为**实时 WS 连接**：`WsHub.Connection` 增加 `connectedAt`，`WsHub` 暴露 `connections()` 快照，`HostServer.onlineDevices()` 映射为 UI 用的 `OnlineDevice(deviceId, name, role, connectedAtMillis)`，按连接时间升序。
- 取舍：不把 `connected_device` 表当列表数据源。该表只服务 REST `/devices` 契约，且 `lastSeen` 仅在连接 / 断开时更新，长连接会被误判离线；实时连接快照天然准确。
- UI：设置弹窗「手机控制端」区块内，二维码与「更换配对码」之下列出「在线设备（N）」；每行「名称 · 手机/平板 · 已连接 X 分钟」（不足 1 分钟显示「刚刚连接」），空态为「暂无设备连接」。
- 刷新：弹窗可见期间每 2 秒调用一次 `refreshHostInfo()`，关闭即停。

### 2.5 日志分级

M7 把 `HostApi` / `HostServer` 的日志回调统一接到 `TpLog.e`，「主机服务已启动」这类正常信息被记成错误级别。M8 把回调拆成 `logInfo` 与 `logError`，`App` / `AppContainer` 分别接 `TpLog.i` / `TpLog.e`。

## 3. 接口与数据模型变化

- 新增 `SettingsStore.hostEnabled`（偏好键 `host_enabled`，默认 `true`）。
- 新增 `host/HostService.kt`（对外仅 `start(context)` / `stop(context)`）与 `host/OnlineDevice.kt`。
- 新增 `HostServer.onlineDevices()`、`HostStatusProvider.onlineDevices()`、`HostStatusProvider.hostEnabled` 读写、`WsHub.connections()`。
- 变更 `WsHub.Connection`：新增 `val connectedAt: Long`。
- 变更日志回调签名：`log: (String, Throwable?) -> Unit` → `logInfo: (String) -> Unit` + `logError: (String, Throwable?) -> Unit`。
- 清单新增权限 `FOREGROUND_SERVICE`、`FOREGROUND_SERVICE_DATA_SYNC`、`POST_NOTIFICATIONS`，新增 `<service>` 声明（`foregroundServiceType="dataSync"`，`exported="false"`）。
- REST / WS 契约、`connected_device` 表结构与库版本（2）均不变。

## 4. 边界与失败场景

- 端口被占用：服务端启动失败，通知显示「服务未启动」，服务本身继续存活以便用户排查端口冲突。
- 无 Wi-Fi：通知显示「未连接 Wi-Fi」，设置页同样提示，二维码不显示。
- 关闭开关：正在编辑菜单的手机会立即断开并需重新连接（已配对的配对码仍然有效，重新打开开关即可再连）。
- 服务被系统杀死：`START_STICKY` 重建后恢复监听；重建期间手机侧按既有设计显示离线并转只读。
- 应用被强行停止（用户在系统设置里「停止」）：系统不会重启服务，属系统行为，不额外补偿。

## 5. 测试与验收

- JVM：`WsHubTest` 覆盖 `connections()` 快照与 `connectedAt` 顺序；`HostApiTest` 全量回归（日志签名变更）。
- 仪表：`HostServiceTest` 覆盖启停（`hostServer?.isServing` 与 `NotificationManager.activeNotifications` 同步变化）、关闭开关后 `/state` 不可达；WS 连接后 `onlineDevices()` 含该设备、断开后为空。
- 真机（Teclast T10 / Android 7.0）：`dumpsys activity services` 可见前台服务与常驻通知；息屏 10 分钟后经 `adb forward` 仍能 `curl /state`；设置页在线列表随连接 / 断线增减；关闭开关后 curl 失败且通知消失，重新打开恢复。

## 6. 实现位置与验证结果（M8）

### 6.1 实现位置

- 前台服务：`host/HostService.kt`（静态入口 `start` / `stop`；`startForeground` 后调用宿主容器的 `ensureHostServerStarted()`，`START_STICKY`；`onDestroy` 内停监听并关闭全部 WS）。
- 装配：`App.kt`（`ensureHostServerStarted()` / `startHostServer()` 改为 `suspend`，新增 `stopHostServer()`；`onCreate` 按 `hostEnabled` 决定是否启动前台服务；服务端就绪后按 7 天保留期清理过期设备记录）。
- 开关与在线设备：`data/SettingsStore.kt`（`host_enabled`）、`host/HostStatus.kt`（`hostEnabled` / `setHostEnabled` / `onlineDevices`）、`host/WsHub.kt`（`Connection.connectedAt`、`connections()`、`pingAll()`）、`host/HostServer.kt`（`onlineDevices()`）、`host/OnlineDevice.kt`。
- UI：`ui/admin/AdminViewModel.kt`（`hostEnabled` / `onlineDevices` 随 `refreshHostInfo()` 一起刷新；开关入口为 `applyHostEnabled()`，命名避开属性 setter 的 JVM 签名冲突）、`ui/admin/AdminScreen.kt`（开关、状态文案、在线设备列表、弹窗可见期间每 2 秒刷新）。
- 资源与清单：`res/drawable/ic_host_service.xml`；`FOREGROUND_SERVICE` / `FOREGROUND_SERVICE_DATA_SYNC` / `POST_NOTIFICATIONS` 权限与 `<service>` 声明。

### 6.2 与设计的偏差

- **WS 心跳（真机暴露的关键缺陷）**：原 `READ_TIMEOUT_MS = 5000` 使空闲连接在 5 秒后被 `SocketTimeoutException` 断开，真机表现为连上后很快静默掉线。修正为 `READ_TIMEOUT_MS = 60_000` 并新增 `PING_INTERVAL_MS = 20_000` 的 ping 协程（`MenuSocket.sendPing()` 发空载荷 ping 帧）；测试侧 WS 客户端相应跳过 `PING` / `PONG` 帧。
- 服务器实例归属：`HostService` 不自持实例，只负责保活与通知，实例仍在 `AppContainer.hostServer`，避免服务与容器互相持有。
- 关闭开关后的状态文案：`HostStatus` 增加 `hostEnabled`，关闭时设置页固定显示「已关闭」，不再误报为「服务未启动（端口被占用）」。

### 6.3 验证结果

- JVM 单测 88 项全绿（新增 `WsHubTest.connectionsSnapshotIsSortedByConnectedAt`、`WsHubTest.pingAllDropsConnectionsThatFailToSend`）。
- 平板（Teclast T10 / API 24）仪表测试 46 项全绿：新增 `host/HostServiceTest`（开关启停与通知同步变化；裸 Socket 握手后在线列表出现该设备、断开后清空）与 `data/PinManagerTest`（见 `0017`）。
- 真机：`dumpsys activity services com.tanpai.menu` 显示 `isForeground=true`；通知 id 1001、图标 `drawable/ic_host_service`；无 token 访问 `/state` 返回 401、带 token 返回完整状态；PC 端 WS 连上后设置页显示「在线设备（1）验收手机 · 手机 · 已连接 1 分钟」，空闲 80 秒仍在线，断开后回到「在线设备（0）/ 暂无设备连接」；关闭开关后服务记录与通知消失、`curl /state` 无响应，重新打开即恢复（日志「主机服务已启动，端口 8080」）。
