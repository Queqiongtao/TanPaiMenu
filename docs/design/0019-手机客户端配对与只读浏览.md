# 0019 手机客户端配对与只读浏览

- 状态：已实现（M10，2026-10-07；Android 9+ 明文 HTTP 兼容修复 2026-10-07）
- 对应阶段：Phase 3（M10）
- 关联：`docs/design/0018-角色选择与客户端运行形态.md`、`docs/design/0002-局域网配对与同步.md`（第 3、4、6.5 节）、`docs/design/0001-菜单数据模型与接口契约.md`、`docs/architecture.md`

## 1. 背景与目标

平板已能对外提供 `/api/v1` 与 `/ws`，但没有客户端。手机要连上平板看菜单，需要一套「配对 → 全量快照 → 增量事件 → 断线只读 → 自动重连」的客户端栈。M10 只做只读浏览（编辑留到 M11），先把手输配对与实时同步这两件最容易出问题的事跑通。

目标：

1. 手输「主机地址 + 6 位一次性配对码」完成配对，换取长期 token 并落盘。
2. 配对后拉 `GET /api/v1/state` 全量快照，再连 `WS /ws` 订阅增量事件；手机端只读展示（分类切换 + 菜品列表：图片 / 菜名 / 价格 / 状态）。
3. 断线进入只读并自动重连（指数退避）；配对失效（401 / 4401）时提示重新配对并停止重试。

## 2. 方案设计（含取舍）

### 2.1 一次性 6 位配对码（主机侧）

- 规则：6 位数字；有效期 5 分钟；一次性（配对成功立即作废）；连续失败 5 次锁定 60 秒；重新生成覆盖旧码并清零失败计数。
- 生成入口：平板设置弹窗「手机控制端」的「显示配对码」按钮（不点即不存在配对码，缩小暴露面）。
- 取舍：不做扫码（省掉相机预览与解码）；不做 NSD 自动发现（工程未实现，且自动发现只能给出地址、给不出凭据）。
- 安全性：5 分钟窗口 + 5 次失败锁定 + 一次性作废，使实际可尝试次数为个位数；按既有前提（摊位专用网络 + 明文 HTTP）接受该风险，配对成功与失败都写 `TpLog` 留痕。

### 2.2 客户端连接流程

1. 输入「主机地址」（`192.168.1.5:8080` 与 `http://192.168.1.5:8080` 均可）与 6 位配对码，设备名默认取机型。
2. `POST /api/v1/pair` → `{token, version}` → 落盘 `clientToken` + `clientHostAddress`。
3. `GET /api/v1/state` → 替换内存镜像；随后连 `ws://<host>/ws?token=&deviceId=&name=&role=client`。
4. 事件应用：`snapshot` 全量替换；`dish.updated` / `category.updated` 按 `version` 大于本地才合并；`dish.deleted` / `category.deleted` 删除（分类删除级联移除其菜品）；`device.*` 忽略；payload 解码失败 → 断开重连并重新拉快照。
5. 断线：转「正在重连」，退避 1/2/4/8/15 秒后固定 15 秒无限重试；每次重连先拉快照再订阅。
6. 401 或 WS 关闭码 4401：转「配对已失效」，停止重试并提示重新配对。

### 2.3 客户端镜像与并发

- `ClientMirror` 是纯内存镜像（不落库），只保存契约 DTO；全部访问都在 `ClientSession` 的单协程内串行，对外只暴露 `StateFlow<ClientMenuState>` 快照，UI 不做并发修改。

### 2.4 网络实现

- 复用已在类路径上的 OkHttp（Coil 传递依赖，升为直接依赖，无新增下载）：REST 连接/读取超时 5 秒；WS 客户端 `readTimeout = 0` + `pingInterval = 20 秒`（与服务端 20 秒心跳呼应）。
- 图片走 Coil；`App` 实现 `ImageLoaderFactory`，仅对主机地址的请求附加 `Authorization: Bearer <token>`，离线时用 Coil 磁盘缓存。
- 回退：若 OkHttp WS 与 NanoWSD 不兼容，改用自研最小 WS 客户端（裸 socket，参考 `HostServerTest` 的既有实现），上层接口不变。
- Android 9+ 明文 HTTP：主机服务仅提供局域网 HTTP，客户端 API 28+ 默认禁止明文流量。Manifest 显式设置 `android:usesCleartextTraffic="true"`，否则 Android 16 手机在 `POST /pair` 阶段会以通用“无法连接平板”失败。该许可只服务摊位专用网络的既有权衡；若未来改公网或需要防窃听，必须升级为 TLS。

## 3. 接口与数据模型变化

新增 `POST /api/v1/pair`（**无需 Bearer**）：

- 请求：`{"code":"123456","deviceId":"<uuid>","name":"手机A"}`
- 响应 200：`{"token":"<64hex>","version":<n>}`
- 失败：`400 invalid_argument`（配对码非 6 位数字、deviceId 缺失）；`401 unauthorized`（错误、过期、已消费、锁定中；message 为中文提示，锁定时含剩余秒）。

其他：

- 新增 `net/protocol` 的 `PairRequest` / `PairResponse` / `IdPayload` DTO 与 `WireEvent.payloadAs<T>()` 解码扩展。
- `SettingsStore` 新增主机侧 `pair_code` / `pair_code_expires_at` / `pair_code_failures` / `pair_code_lock_until` / `paired_device_name`，客户端侧 `clientHostAddress` / `clientToken` / `clientDeviceName`。
- `HostApi` 新增独立入口 `handlePair(request)`（与 `handleImageUpload` 同级，显式跳过统一鉴权）。

## 4. 边界与失败场景

- 地址非法：连接页即时提示「地址格式应为 IP:端口」。
- 主机不可达或超时：提示「无法连接主机，请确认与平板在同一 Wi-Fi」。
- 配对码错误 / 过期 / 锁定：显示主机返回的中文 message（锁定含剩余秒）。
- 平板关闭「手机控制端」开关：手机断线转只读；平板重新打开后自动恢复。
- 平板更换配对码：旧 token 立即失效 → 手机提示重新配对。
- 手机切到后台：不主动断开；进程被回收后回到前台按第 2.2 节流程重连。

## 5. 测试与验收

- JVM：配对码规则（生成 / 过期 / 一次性 / 5 次失败锁定 / 锁定内正确码拒绝 / 重新生成清计数）；`POST /pair` 契约（200 / 400 / 401 / 锁定 / 无需 Bearer）；`ClientMirror`（快照替换、旧版本丢弃、合并、删除与级联）；地址规范化；`WireEvent` payload 解码；重连退避序列。
- 仪表：真实 `HostServer` + 客户端栈（连 `127.0.0.1`）跑通「配对 → 快照 → 改价收 `dish.updated` → 停服离线 → 重启自愈」。
- 真机双机：手机输入平板地址 + 6 位码看到 12 道菜；平板改价手机 1 秒内更新；手机断网出现只读条幅、恢复后自动重连；平板关闭开关手机离线、重新打开自愈；平板在线设备列表可见该手机。

## 6. 实现位置与验证结果（M10，2026-10-07）

- 主机侧：`host/PairCodeManager.kt`（规则与 `PairVerdict` / `PairCodeStatus`）、`data/PairCodeStore.kt`（存储抽象，由 `SettingsStore` 实现）、`host/HostApi.handlePair`（400 / 401 映射）、`host/HostServer`（`/pair` 在鉴权管线外分流）、`host/HostStatus.generatePairCode()` / `pairCodeStatus()`、`ui/admin/`（设置弹窗「显示配对码」区块）。
- 契约：`net/protocol/Contract.kt` 的 `PairRequest` / `PairResponse` / `IdPayload`，`net/protocol/EventPayload.kt` 的 `WireEvent.payloadAs<T>()`。
- 客户端：`net/HostAddress.kt`、`net/HostRestClient.kt`、`net/MenuSocketClient.kt`、`client/ClientMirror.kt`、`client/ClientSession.kt`、`client/PairingClient.kt`、`client/ReconnectionPolicy.kt`。
- 界面：`ui/client/ClientApp.kt`、`ClientConnectScreen.kt`、`ClientMenuScreen.kt`、`ClientSettingsDialog.kt`。
- 验证：JVM 单测 128 项通过（新增配对码规则、地址规范化、payload 解码、镜像、退避与 `/pair` 契约用例）；平板仪表测试 47 项通过，其中 `ClientSessionTest` 用真实 OkHttp 连本机 `HostServer` 跑通「配对 → 快照 → 改价收 `dish.updated` → 停服离线只读 → 重启自愈」。
- 实现中修复：`HostRestClient` 原先直接拼接用户输入的主机地址，`GET /state` 会因缺少 scheme 失败；现统一由 `HostAddress.normalize` 在客户端内部规范化（`PairingClient` 仍保留一次前置校验用于中文提示）。
- 已知偏差：WS 关闭码 4401 与 401 两条失效路径均已实现，但「平板更换长期令牌」后手机端只提示重新配对，不做自动重新配对。原偏差「`/state` 未下发店名、客户端标题固定为「菜单」」已由 M11 修复：`/state` 与 `snapshot` 帧均带 `storeName`（`docs/design/0020`）。

## 7. 未决事项

- 手机端编辑（增删改、图片上传、卖出/撤销/沽清）：已完成，见 `docs/design/0020`（M11）；同步策略为「提交即禁用、等广播对齐」，不做乐观更新与回滚。
- 扫码配对、NSD 自动发现：后续可扩展。

## 8. Android 9+ 兼容修复与双机验收（2026-10-07）

- 问题：Android 16 手机目标 SDK 34，系统默认禁止明文 HTTP；旧 Manifest 未声明 cleartext，手机能 ping 通平板且主机端口正常，但 `POST /pair` 被系统网络策略拦截，客户端只显示通用“无法连接平板”。
- 修复：在 `<application>` 上设置 `android:usesCleartextTraffic="true"`。主机与客户端仍限摊位专用局域网，风险边界不变；未来若跨公网，应改为 TLS。
- 双机证据：Android 7 平板 `192.168.51.177:8080` 与 Android 16 手机 `192.168.51.227` 完成配对、快照、改价、库存、卖出两次自动沽清、撤销、分类 / 菜品编辑、相册图片上传和自动重连。
- 权限证据：关闭“允许手机编辑”后手机显示“平板已关闭手机编辑”并保持只读；重新开启后恢复正常在线和编辑入口。后台 403 语义仍由 `HostServerTest.clientWriteIsForbiddenWhenEditsDisabled` 自动覆盖。
- 收尾证据：手机恢复默认菜单后两端均为 12 道；手机清除本地配对；平板更换长期令牌后旧 token 访问 `/state` 返回 401。
- 自动化限制：MIUI/Android 16 对 ADB 注入的分类长按不稳定；分类改名 / 删除以手机持有的真实 token 调用 REST，并验证两端 UI 同步，其他编辑动作均由手机界面完成。
