# 0010 展示页微信二维码

- 状态：已实现（2026-10-06）
- 对应阶段：Phase 1 修订（展示页外观）
- 关联：`docs/design/0007-展示页背景图片.md`、`docs/design/0009-展示页内置背景样式.md`、`docs/design/0006-展示页紧凑布局与默认菜单.md`、`docs/architecture.md`

## 1. 背景与目标

店主希望在展示页上放自己的微信二维码，方便顾客现场「加微信」。顶栏右侧已被分类胶囊占用，因此二维码放在店名左侧。

目标：

- 展示页顶栏店名**左侧**常驻一个二维码入口：小码 + 「加微信」提示文字。
- 二维码由店主自行上传（相册选择 / 拍照），入口在管理页设置弹窗。
- 点击小码弹出全屏大码便于顾客扫，**展开 5 秒后自动复原**，点击任意处可立即关闭。
- 未设置二维码时顶栏与改动前完全一致。
- 不新增第三方依赖、不改动数据模型与备份格式。

## 2. 方案设计（含取舍）

### 2.1 位置与宽度预算

顶栏高 72dp，店名招牌居中（≤ 40% 顶栏宽），分类胶囊靠右（≤ 30%）。左侧新增入口块后三者互不重叠：

| 区域 | 内容 | 宽度上限 |
| --- | --- | --- |
| 左 | 小码 56dp + 8dp 间距 + 「加微信」13sp | ≈ 104dp（约 11%） |
| 中 | 店名招牌 | 40% |
| 右 | 分类胶囊（> 1 个分类时） | 30% |

取舍：不做顶栏加高——加高会挤掉「12 道一屏」，而点击放大已能解决扫码距离问题。

### 2.2 入口块

- 56dp 白底圆角方块（圆角 10dp，内边距 4dp）承载二维码，白底保证在深色背景图 / 样式上仍有足够对比度。
- 「加微信」用 `primary` 13sp，横排在二维码右侧。
- 整个入口块（含文字）统一可点，点击即展开浮层。

### 2.3 放大浮层

- 全屏 `Black 78%` 遮罩 + 居中白色圆角卡片（圆角 24dp、内边距 24dp）；卡片内含「加微信」28sp 标题、大二维码、「点击任意处关闭」提示。
- 大码边长 = `min(可用宽 × 0.6, 可用高 × 0.92 − 160dp, 480dp)`：高度项预留卡片内边距、标题与关闭提示（约 160dp），保证卡片不超屏；本机（961dp 宽 / 601dp 高）取 393dp ≈ 6.2cm，桌上距离可扫。
- 浮层挂在 `DisplayScreen` 根 `Box` 最后一层，覆盖顶栏与菜品网格。

### 2.4 自动复原

- 常量 `WECHAT_QR_AUTO_COLLAPSE_MILLIS = 5_000L`，`LaunchedEffect` 内 `delay` 到点自动关闭；点击遮罩立即关闭。
- 关闭后再点小码可重新展开并重新计时（计时随浮层生命周期启停，不会叠加）。

### 2.5 图片导入：无损 PNG

二维码是高对比硬边内容，JPEG 压缩产生的振铃会影响识别率，因此新增 `ImageStore.importLosslessFromUri(uri, maxEdge = 1024)`，输出 **PNG 无损**：

- 与 `importFromUri` 共用同一套私有缩放解码逻辑，避免重复实现。
- `maxEdge = 1024` 与本机大码显示边长（约 393dp ≈ 1046px）基本相当（最多约 2% 放大），保证清晰度且体积很小（约几十 KB）。
- 现有 `importFromUri` 签名与行为不变，背景图 / 菜品图零影响。
- 存储层无需改动：`delete`、`deleteOrphans`、`writeImage` 的 `IMAGE_NAME` 正则均已支持 `.png`。

### 2.6 设置项与孤儿图保护

| 设置项 | key | 取值 | 默认 |
| --- | --- | --- | --- |
| 微信二维码相对路径 | `wechat_qr_image` | `images/<uuid>.png` 或空 | 空（未设置） |

- 复用 `images/` 目录与 `ImageStore`，不新增目录与数据表。
- 二维码不属于任何菜品，必须加入启动孤儿图清理与「恢复默认菜单」的保留集合，否则每次冷启动会被删除（与背景图同类问题）。
- 不参与导出 / 导入备份，与背景图、内置样式、蒙版一致，`backup.json` 仍为 `format 1`。

### 2.7 采集流程收敛

原「图库 / 拍照 / 相机权限」三个 launcher 只服务背景图，且权限拒绝状态只有一个。新增二维码后改为**单套带目标**的流程：

- `ImageTarget { Background, WechatQr }` + `pendingTarget`，一个图库 launcher、一个拍照 launcher、一个权限 launcher。
- 失败与权限拒绝状态改为按目标记录（`failedTarget` / `deniedTarget`），提示显示在各自分区内。
- 取舍：比复制一整套 launcher 更少重复，且不会出现两套流程争用同一 `permissionDenied` 状态。

## 4. 边界与失败场景

| 场景 | 处理 |
| --- | --- |
| 未设置二维码 | 顶栏左侧不渲染，展示页与旧版一致 |
| 二维码文件被外部删除 | `File.exists()` 为假则不渲染入口，不崩溃 |
| 相册 / 拍照无法解码 | 导入返回 null，分区内提示「背景图读取失败，请重新选择」同款文案 |
| 未授予相机权限 | 分区内提示「未授予相机权限，无法拍照」 |
| 换图 / 清除 | 主动删除旧文件，避免残留 |
| 浮层展开期间点击 | 立即关闭；再点小码可重新展开并重新计时 |
| 同时设置背景图 / 内置样式 | 互不影响，二维码独立渲染 |

## 5. 测试与验收

- 仪表测试 `WechatQrOverlayTest`：展开后浮层可见；约 5 秒后自动消失；点击遮罩立即消失。
- 真机手工验收：相册 / 拍照 / 清除各走一遍；顶栏小码与「加微信」显示正常、与店名和分类胶囊不重叠；点击放大→5 秒自动复原、点击立即复原；未设置时与旧版一致；冷启动保持；「恢复默认菜单」后仍在；12 道一屏不滚动无回归。
- 构建门禁：`assembleDebug` + `testDebugUnitTest` 通过，无新增资源与依赖，APK 体积无明显变化。

## 6. 验证记录

- 构建与单测：2026-10-06，JDK 17 + Gradle 8.9，`assembleDebug`、`testDebugUnitTest` 通过。
- 仪表测试：Teclast T10（API 24）`connectedDebugAndroidTest` **16 项全通过**，含 `WechatQrOverlayTest` 3 项（展开可见、约 5 秒自动复原、点击立即复原）与 `ImageStoreLosslessTest` 2 项（导入落盘 `.png`、长边缩放到 1024）。
- 真机截图：顶栏左上小码 + 「加微信」与居中店名招牌、分类胶囊互不重叠，12 道仍一屏；点击后放大浮层完整可见、「点击任意处关闭」未被裁切；约 5 秒后自动复原为展示页。
- 冷启动保持：重装后冷启动，二维码入口正常渲染，未被启动孤儿图清理删除。
- 未覆盖（需真机手工验收）：相册选择 / 拍照导入、清除旧图、相机权限拒绝提示；暂未在多机型 / 多分辨率上验证。
