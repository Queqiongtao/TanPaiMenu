# 0017 管理密码重置与修改

- 状态：已实现
- 对应阶段：Phase 1 修订（门禁能力补齐）
- 关联：`docs/design/0003-平板运行形态与门禁.md`、`docs/architecture.md`

## 1. 背景与目标

Phase 1 的门禁只有「首次设置密码」与「输入密码」两条路径，没有任何修改或重置入口。真机验证时确认：一旦忘记管理密码，唯一出路是清除应用数据，菜单与图片一并丢失；店主想换密码也同样无解。

本次目标：

1. 已进入管理页时可「修改管理密码」（校验旧码）与「关闭密码保护」（校验旧码 + 二次确认）。
2. 忘记密码时提供「忘记密码」通道：长按 3 秒 + 二次确认后清除管理密码，并**强制设置新密码**进入管理页，菜单与图片不受影响。

## 2. 方案设计（含取舍）

### 2.1 已登录侧：修改与关闭

- 设置弹窗新增「管理密码」区块，两项入口：
  - 「修改管理密码」：输入旧密码 → 输入新密码 + 确认（沿用 4-6 位数字与两次一致的校验）→ `PinManager.setPin` 重新生成盐值。
  - 「关闭密码保护」：输入旧密码 → 二次确认（提示关闭后长按店名即可直接进入管理）→ `PinManager.clearPin()`。
- 两项入口都需要旧密码，避免开着管理页被旁人顺手改掉。

### 2.2 忘记密码侧：长按重置

- `PinEntryDialog` 底部新增「忘记密码」，需**长按 3 秒**触发，弹出二次确认（说明将清除当前管理密码并重新设置，菜单与图片保留）。
- 确认后：`clearPin()` → 立即切到「设置管理密码」弹窗且不可取消回到展示页 → 设置完成进入管理页。
- 记录 `TpLog.w("pin", "通过忘记密码通道重置管理密码")` 留痕。

### 2.3 取舍与风险

- 免密重置通道客观上削弱门禁：知道该操作的顾客也能重置密码后改价。取舍理由是「摊主忘记密码的损失（菜单与图片全丢）远大于被恶作剧改价」，并用「长按 3 秒 + 二次确认 + 强制重设」把误触概率压到很低。
- 未采用「恢复码 / 邮箱找回」：工程没有账号体系与网络后端，引入恢复码等于把码写在现场，收益与复杂度不成比例。

## 3. 接口与数据模型变化

- 新增 `PinManager.clearPin()`：清空 `admin_pin_hash`、`admin_pin_salt`、失败计数与锁定时间；偏好键不变，无库迁移。
- 新增文案（`res/values/strings.xml`）：管理密码区块标题、修改 / 关闭入口、旧密码校验提示、忘记密码长按提示与二次确认文案。
- `PinEntryDialog` 增加忘记密码入口；新增修改密码弹窗（复用现有密码表单样式）。

## 4. 边界与失败场景

- 旧密码错误：沿用既有失败计数与 60 秒锁定策略，不额外放宽。
- 关闭密码保护后：长按店名直接进入管理页，不再弹出输入框。
- 忘记密码流程中途退出（未设置新密码）：密码已清除，下次长按会重新进入「设置管理密码」，不会卡死。
- 重置过程中断（进程被杀）：`clearPin()` 已落盘，效果同上。

## 5. 测试与验收

- 仪表：`clearPin()` 后 `isPinSet()` 为假、长按可直接进管理页；「修改管理密码」用新密码可进入、旧密码被拒；「忘记密码」长按 3 秒后清除密码并进入设置新密码流程。
- 真机：设置页关闭密码保护 → 长按店名直接进入；重新设置密码 → 长按需输入新密码。
- 门禁：`gradlew :app:testDebugUnitTest :app:connectedDebugAndroidTest` 全绿。

## 6. 实现位置与验证结果

- 数据层：`data/PinManager.kt` 新增 `clearPin()`（清 `admin_pin_hash`、`admin_pin_salt`、失败计数与锁定时间；无库迁移）。
- 组件：`ui/admin/AdminDialogs.kt` 新增 `HoldToTriggerButton`（长按触发并显示进度百分比）、`PinChangeDialog`（旧码 → 新码，旧码错误沿用失败计数与 60 秒锁定）、`PinDisableDialog`（旧码 → 二次确认 → `clearPin()`）。
- 装配：`ui/TanPaiMenuApp.kt` 新增 `pinSetupForced`（重置后「设置管理密码」不可取消，`FORGOT_HOLD_MS = 3_000`）；`ui/admin/AdminScreen.kt` 设置弹窗新增「管理密码」区块与两个弹窗挂载。
- 文案：`settings_pin_title/change/disable/disable_confirm/changed/disabled`、`pin_change_title/old_label/forgot/forgot_hint/forgot_confirm/forgot_title/forgot_action`。
- 验证：仪表 `data/PinManagerTest` 覆盖 `clearPin()` 后不再要求密码、`setPin()` 替换旧码；真机走通「忘记密码长按 3 秒 → 二次确认 → 强制设置新密码 → 新码可进管理页」与「关闭密码保护 → 长按店名直接进入管理页」；设置页在已设密码时显示「修改管理密码 / 关闭密码保护」，重置流程中「设置管理密码」不含取消入口。
