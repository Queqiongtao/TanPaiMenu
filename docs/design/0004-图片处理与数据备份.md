# 0004 图片处理与数据备份

- 状态：已实现（图片本地存储与 JSON 备份；Phase 4 已升级 format 2）
- 对应阶段：Phase 1 / Phase 2
- 关联：`docs/design/0001-菜单数据模型与接口契约.md`

## 1. 背景与目标

约定菜品图片的压缩、存储、引用与清理规则，以及菜单数据的 JSON 导出 / 导入格式，保证现场换机与误操作可恢复。

## 2. 图片

- 来源：相册选择、拍照。
- 限制：仅 `image/jpeg`、`image/png`，单张 ≤ 10MB（超过返回 413）。
- 处理：长边压到 ≤ 1280px，JPEG 质量 80，统一转存为 JPEG。
- 存储：`filesDir/images/<uuid>.jpg`；`Dish.imagePath` 存相对路径。
- 访问：`GET /api/v1/images/{name}`，文件名校验 `^[0-9a-f-]{36}\.(jpg|png)$`。
- 清理：替换图片或删除菜品时删除旧文件；启动时清理无引用的孤儿图片。
- 缺省：无图时展示菜名首字占位卡。

## 3. 备份格式（JSON）

```json
{
  format: 2,
  exportedAt: 2026-10-05T03:20:30.123Z,
  app: TanPaiMenu,
  categories: [],
  dishes: [],
  images: [images/<uuid>.jpg]
}
```

- `format`：备份格式版本，当前为 2；导入时高于支持版本则拒绝并提示。format 1 可读，旧数据没有标签字段时按 null 处理。
- 导入语义：整库覆盖（清空后写入），导入前二次确认。
- id 保留：导出 / 导入保留原 id，保证 `SaleRecord` 与 `imagePath` 引用不失效。
- 图片：图片文件放在同一目录的 `images/` 下随备份一起拷贝；缺失图片时菜品降级为首字占位。
- 菜品标签：`BackupDish.highlight` 可为 null；不改变既有图片与菜单覆盖语义。

## 4. 边界与失败场景

- 导入损坏或缺字段：校验失败即中止，不修改现有数据。
- 导入时磁盘不足：中止并提示，保留原数据。
- 跨版本备份：`format` 不兼容则提示，不尝试猜测。

## 5. 测试与验收

- 导出 → 清除数据 → 导入，菜单与图片完整还原。
- 超大或错误 MIME 图片被拒绝。
- 删除菜品后对应图片文件被清理。

## 6. 未决事项

- 是否支持自动定时导出（当前仅手动）。

## 7. 实现位置与验证结果（Phase 1）

- 图片：`imaging/ImageStore.kt`（相册 / 拍照导入、长边 ≤1280 的采样与缩放、JPEG 质量 80、`filesDir/images/<uuid>.jpg`、孤儿清理、备份导入时按 UUID 文件名白名单校验）。
- 备份：`backup/BackupFormat.kt`（`format 2` 的序列化与校验，兼容读取 format 1）、`backup/BackupManager.kt`（SAF 目录树 I/O，导出 `backup.json` + `images/`；导入先解析校验，再事务整库覆盖，最后回写图片）、`data/MenuRepository.kt` 的 `exportAll/replaceAll`。
- UI：`ui/admin/AdminScreen.kt` 设置对话框中的「导出备份 / 导入备份」+ 导入二次确认 + 结果提示。
- 真机验证：相册导入 1600x2560 截图 → 落盘 41KB JPEG，对话框与展示卡片均正确显示（无拉伸）；导出得到 `format 1` 的 `backup.json` 与 `images/`；卖出使余量 18→17 后导入备份恢复为 18；`BackupCodecTest` 10 项单测覆盖字段名、版本兼容、缺字段与损坏 JSON 场景。
